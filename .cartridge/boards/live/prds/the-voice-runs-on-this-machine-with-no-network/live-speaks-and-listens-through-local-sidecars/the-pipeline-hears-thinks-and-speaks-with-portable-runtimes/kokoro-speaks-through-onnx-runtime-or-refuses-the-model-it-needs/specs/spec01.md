## Implementation

1. Pin `ort = "=2.0.0-rc.13"` and `misaki-rs = { version = "=0.6.0", default-features = false }`; lock dependencies. Add `sha2` only as a dev dependency if used to validate fixture identity. Misaki 0.6 uses `G2P::new(Language::EnglishUS)` and returns a Result from `g2p`; older README examples using a bool/tuple are stale. Disabling espeak gives an embedded Rust lexicon and an explicitly documented letter-spelling fallback for unknown English words; unknown characters must produce a readable error if there are no speakable tokens, not fake silence.
2. Add `mod kokoro;` in local.rs, implemented in `src/local/kokoro.rs`. Resolve and validate the model and two companions with filename-bearing errors. Validate voice byte alignment and exactly 510 rows of 256 little-endian f32 values, all finite; validate the tokenizer's `model.vocab`, usable character IDs and zero boundary token. Parse without unchecked slices or unwraps on external data. Check the model inputs before use: `input_ids` int64 [1, sequence], `style` float32 [1,256], `speed` float32 [1]; require the named `waveform` float32 output [1, samples] used by the pinned export; look it up by name, not positional index zero. Reject incompatible files with model-path context.
3. Phonemize ordinary English with Misaki. Normalize/filter the phoneme characters according to the bundled tokenizer vocabulary, preserving punctuation and spaces; never treat raw orthographic character IDs as phonemes. Produce ordered chunks of at most 510 token IDs, preferably at whitespace or punctuation, with no loss or duplication. Add zero tokens at both boundaries. For n content tokens choose voice row n-1, matching upstream Kokoro's current pipeline; pass speed [1.0]. Handle empty/whitespace-only input deliberately (no audio delta), and reject nonempty input that produces no usable speech. Run the real session. Reject empty or nonfinite inference output, convert finite samples to saturated signed 16-bit PCM at 24,000 Hz, and preserve the existing base64 little-endian event contract. Only bounded output within the limits below may produce one combined PCM vector in this leaf; do not claim clause streaming. Distinguish empty/whitespace-only input (no audio) from punctuation-only and unsupported-character-only input (readable refusal because neither contains a speakable phoneme).
4. Hold one loaded ONNX session, voice/tokenizer and G2P per local session and reuse it. Construct this state inside one `spawn_blocking` worker and communicate owned requests/results over a capacity-one worker channel and oneshots. Retain its JoinHandle in the session task; the task dispatches at most one outstanding synthesis and never preloads a second utterance into the worker. Construct the potentially non-Send G2P inside that worker. Apply the admission, cancellation and reaping protocol below to initialization as well as inference. Never run phonemization/inference or a blocking join on an async runtime worker, reload weights per utterance, call the service while holding an ingress mutex, or share a global model session across cartridges.
5. Prepare the model speaker before the local loop performs any STT or brain dial, without loading any model when TTS is an endpoint. Preserve the existing missing-STT behavior. Keep initial `session.started` and existing service callback semantics; avoid changing service.rs for this leaf. The existing service status test remains the backstop for error retention.
6. Replace `Session::send`'s no-op with the typed, bounded ingress below; also replace the existing unbounded microphone queue. Use the responsive session reactor described below, which continues consuming capture while a single reply pipeline is in flight, so ordinary quiet capture never waits behind inference. `session.commentary.append` with nonempty content is a voice update: ask the configured brain for a concise spoken response to that update (including instructions such as the service greeting), then emit output transcript followed by speech through the same prepared speaker, without STT or a new user-question assessment/delegation. Unknown control events remain non-speaking. A failed commentary brain/TTS stage follows the same error-close contract, using the first-terminal-wins protocol below. Tests must use the service's actual event shape, including delegation_id, rather than a made-up direct-speech API.
7. ## Bounded admission and work

These are internal constants, not new settings. They apply to the local transport, including its HTTP stand-ins. GPT transport behavior is unchanged. Reject an oversized utterance with a readable terminal error, never silently truncate its speech. Rolling *silent context* is explicitly allowed to evict old context as documented.

| Resource | Limit and enforcement |
| --- | --- |
| Accepted ingress | 32 items and 128 KiB of payload bytes **including any pending/active commentary or context item and a frame until the reactor consumes it**. Audio counts `samples * 2`; text and any retained identifier count UTF-8 bytes. Each item owns an accounting permit until consumed or discarded. Queue metadata has a fixed item bound. |
| One audio ingress item | 9,600 i16 samples (400 ms at 24 kHz). Check borrowed slice length and reserve admission before copying; empty frames are ignored. |
| One commentary/context item | 8 KiB UTF-8 content plus at most 256 bytes of retained delegation ID. Extract only recognized typed fields from the owned Value; do not retain arbitrary caller JSON. Unknown events are discarded without copying/queueing. Check sizes before copying. |
| Collected microphone turns | One current job and at most one later capture turn, each at most 720,000 samples (30 seconds, including pre-roll and terminating silence). Only the later slot is mutable during a reply. Before speech and after a later turn commits, retain only a separate 4,800-sample idle pre-roll. Check capacity before extension; excess real speech terminates explicitly as described below. |
| Brain and STT HTTP response body | 64 KiB each. Reject excessive Content-Length immediately when present; otherwise read `Response::chunk()` incrementally and check remaining capacity **before extending** the body buffer. Parse JSON only after the bounded read succeeds. Preserve the existing 3-second request timeout. Chunked/no-length bodies get exactly the same bound. |
| Parsed transcript / generated spoken text | 8 KiB UTF-8 each, checked before event publication, brain request construction or phonemization as appropriate. An oversized generated answer fails before entering the speaker. Brain requests include a concise-reply instruction, but that instruction is not the enforcement mechanism. |
| Retained silent context | 32 KiB UTF-8 total, oldest context evicted on character boundaries. The ingress limit applies before context reaches this storage. |
| Phonemized content | At most 2,040 content token IDs per utterance (four 510-token model chunks). Stop collecting IDs at limit+1 and refuse the entire utterance **before any inference chunk starts**. The input text bound also applies before invoking G2P. |
| PCM output | At most 720,000 mono samples total per utterance (30 seconds). Before copying a model output tensor into application accumulation, validate named output shape, finite samples, and remaining sample budget. Never emit a prefix of an over-budget utterance. HTTP TTS is read incrementally with the equivalent 1,440,000-byte cap; reject odd byte counts rather than dropping the final byte. |
| Error reason | At most 1 KiB UTF-8 retained in terminal control state. Include the limit/operation or bounded path excerpt. Never retain an entire rejected payload as the reason. |

The PCM cap bounds application accumulation and emitted audio, not ONNX Runtime's internal allocator or arbitrary malformed graphs. The supported model is the documented Kokoro export; do not claim an OS memory quota for the native runtime. Check count/shape before copying model-owned output, and avoid a second unbounded PCM allocation during base64 conversion. Its encoded bound follows mechanically from the PCM cap.

Implement one shared admission/control object with a short mutex-protected state (`Running`, or terminal reason), accepted item/byte counters, and a separate wakeable stop signal (for example a Tokio watch channel). `Session::send` and `audio` atomically check Running, check/reserve both budgets, and try-send the typed item. They never wait for queue room. They return promptly without invoking `on_event`, awaiting, or entering native inference. Full item/byte budget or oversized input requests terminal overload in the shared state and wakes the session task. Later calls cannot admit more work. Keep an accounting permit on the item; release it exactly once on consumption/discard, without recursively locking the admission mutex. The bounded mpsc queue can have capacity 32; the shared permit budget also includes pending/active control items, so it is the tighter authoritative bound. Moving a commentary item from ingress into pending jobs retains its permit; it does not create room by hiding queued text elsewhere. Consuming an audio frame releases its ingress permit after the bounded capture update, rather than retaining every raw frame until synthesis completes. The separately bounded current/later turn slots account for retained capture samples.

Only the session task emits the overload `error` followed by `session.closed`, after releasing any admission lock. This matters because Service::speak calls `Session::send` while holding its live-map mutex. There must be no callback path from send/audio/close or their Drop implementations, including exceptional paths. Avoid holding any session-control mutex during callbacks, network I/O, G2P or native inference.

## Responsive capture during a reply

The session task is a reactor, not the old `recv -> await commit -> recv` loop. Keep one active reply pipeline (STT, assessment, brain, TTS stages) represented by a polled future/state machine, while the same task continues to service ingress and the capture-stall timer. At each iteration check stop first. Among nonterminal ready work, poll the active stage/result, ingress and timer fairly; do not let a ready audio stream starve reply completion, or let a pending stage stop ingress consumption. Perform only bounded frame bookkeeping in the reactor. The Kokoro worker still runs native work away from async threads. The reactor alone reserves/publishes callbacks and starts new stages under the existing cancellation contract. Stage results/requests use bounded snapshots, so the task can update capture/context without borrowing mutable state across a long await.

Quiet audio is processed with the existing `Turn::hear`, `heard_speech` and `committed` methods, not a new VAD or a duplicated threshold. While no later speech has begun, consume each accepted frame promptly and overwrite the fixed 4,800-sample pre-roll with the latest idle samples. No quiet-only turn is submitted to STT. A valid assessment/brain/inference that remains in flight for many capture batches therefore retains only the pre-roll plus a transient bounded ingress frame, not every quiet batch. This rule also applies during model initialization. It does not depend on playback already being marked as speaking and does not suppress all capture while busy.

There is exactly one later-turn slot in addition to the active job's audio:

1. When a frame first marks speech, move the existing idle pre-roll and that entire frame into the later slot, then preserve every subsequent frame in order up to the existing content-based turn boundary or genuine capture stall. Enforce the 720,000-sample cap before copying; never replace voiced audio with newer samples. The slot can fill while the prior reply is assessing, calling the brain or synthesizing. No second STT/brain/inference pipeline starts concurrently.
2. On commit, freeze that slot and enqueue its small job marker behind already-pending commentary jobs. Commentary order is admission order; an audio job joins this same FIFO at its commit point. Pending commentary retains its original item/byte permit. The job list contains at most 32 permitted text items and one later-turn marker; it cannot be an unbounded second ingress. The committed slot stays occupied until its job becomes active. Taking it into the active job frees the later slot and resets capture turn state.
3. While a committed later slot waits, keep consuming quiet frames into only the fixed idle pre-roll. They neither alter the frozen turn nor start another job. Classify a new frame with a fresh existing Turn detector: if it contains genuine speech while the later slot is still committed, request terminal `local speech backlog is full` rather than silently dropping it, replacing the frozen turn, or appending two user questions together. A still-uncommitted later utterance exceeding 30 seconds gets the distinct turn-too-long error. These are explicit finite-capacity policies for additional real speech, not penalties for idle silence.
4. Once the active reply finishes, publish its permitted transcript/audio in their existing order and start the oldest pending job. A later user turn accepted while the reply was busy is transcribed exactly once after earlier jobs, with every accepted voiced sample preserved in order. There is no barge-in/preemption change in this leaf; the turn-taking/duplex owners retain that scope.

Bounded storage is thus ingress/control 128 KiB and 32 items, one current audio job at most 1,440,000 bytes, one later capture turn at most 1,440,000 bytes, and idle pre-roll 9,600 bytes, plus the previously bounded context/HTTP/text/PCM and model state. Current audio may be released after STT consumes it. A raw audio frame's ingress permit is released after processing, but samples that have begun a real later turn remain in its explicit bounded slot. Quiet coalescing cannot erase speech already accepted into that slot. Whole-frame acceptance, frame-processing acknowledgment in tests, and slot occupation/commit transitions make this checkable.

The stall timer measures the last **processed capture arrival** and is reset by every frame, including quiet frames during a reply; it is not a timeout on receiving commentary/control events. When capture truly stops, it may commit an in-progress later turn under the existing STALL rule. It never turns idle pre-roll into a user turn. Stop drains both pending job markers/permits and the later capture slot, preserving the previous first-terminal-wins and native-worker reaping contract.

The deliberate burst overload policy still applies: sending more than the ingress budget before the reactor can process it may terminate the session. The normal microphone case has recurring capture processing between frames. Do not enlarge the ingress budget, make inference artificially fast, discard all busy speech, or transfer raw frames into an unbounded side queue to satisfy the success test.

## Prioritized close and worker cleanup

`Session::close` is a control signal outside the FIFO. Under the same admission gate it installs normal-close terminal state if still Running, rejects subsequent input and wakes the session task. An ingress overload or asynchronous stage failure uses the same first-terminal-wins operation. Once stopped, a later error cannot turn a normal close into an error, and later closes cannot erase an already-selected error. Only one task owns terminal event publication and cleanup. Normal close publishes one `session.closed`; failure publishes one `error` then one `session.closed`. The errors specified for missing assets remain synchronous preflight events during connect where the service already buffers startup callbacks; send/audio/close never emit them.

Separate client-handle ownership from task/control ownership: clones of Session share a client-ingress owner, and dropping its **last** clone requests normal close. The session task must not itself retain that client owner. Dropping one of several clones does not stop the others. The receiver and task may retain the control state, not a hidden extra client sender that prevents last-client shutdown.

The session task selects stop ahead of ready ordinary work and ahead of completion results at every await boundary, including model initialization, STT, assessment, brain, and speaker response. Recheck terminal state before reserving the next stage and before publishing a nonterminal callback. Stage/publication reservations under the admission gate define the race boundary; no new item or stage can be reserved after terminal state is installed. No service callback runs under that gate. A callback already reserved before close can finish (it cannot safely be retracted or waited on by a caller holding the service lock); the completed result of an inference held across close is never reserved for publication and is discarded. This explicit cooperative boundary must not be described as preempting an already-entered native call or callback.

On stop, close/drain the ingress receiver, release queued permits and the active item's permit, clear current/later collected audio, pre-roll, pending job markers and context, drop outstanding async network/assessment futures, and close the speaker request sender. The native worker observes shared cancellation before starting initialization if not begun, before phonemization, before every model chunk, and before sending any result. It finishes at most the currently executing native operation, discards its result after cancellation, skips every remaining chunk, then destroys its state. Because there is only one submitted request, a second queued utterance cannot survive in the worker. Initialization follows the same protocol: if close arrives during loading, finish that native load, destroy it and never begin synthesis.

The async session task awaits the retained blocking-worker JoinHandle exactly once; this yields the async executor rather than calling a blocking thread join. It does not await inference while holding a service or ingress lock. Publish terminal events promptly upon observing stop, then remain alive to reap that handle; terminal publication alone is not evidence that native resources have already been released. Do not detach the worker on timeout or abort its JoinHandle: a running spawn_blocking operation cannot be forcibly cancelled that way. Native inference may finish after logical session closure, but it cannot produce more audio, start a later chunk, or consume queued work. A worker panic/initialization error/inference error maps into the same terminal state and cleanup; pending queued work is discarded, not retried. Tests await an internal task-completion/join receipt to prove reaping, not only the closed event or a Drop flag.
