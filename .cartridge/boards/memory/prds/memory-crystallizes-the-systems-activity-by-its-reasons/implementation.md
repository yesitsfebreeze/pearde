The implementation is integrated in memory.ctg. Development used the isolated .worktrees/memory-crystallization checkout against baseline 1d1bb31. Integration compared every touched path against that baseline, preserved concurrent README, help and manifest changes with a three-way merge, and kept reversible copies before writing. Changes remain in the working tree; this record does not claim PRD collection. Live memory activation is verified below.

## Delivered behavior

Observations become graph-native entities with semantic provenance reasons and explicit recurrence annotations. Compatible repetitions increment occurrence count and decayed heat. Opposite outcomes and incompatible reasons stay separate. Exact repeats skip embedding and ANN search. Retirement invalidates an already-prepared exact shortcut; the retry embeds and creates a new generation without overwriting history.

Durable intake, delivery receipts and changed-memory persistence share one atomic commit. Rollback restores only touched memories and indexes. Unload/load preserves recurrence; unreadable unloaded memories cause refusal rather than replacement. Embedding failures and stale commits retain inputs. Receipts enforce the bounded delivery window. Existing large raw rows decode through the migration path without the new live-input payload cap. Each engine owns its crystallization lock, so unrelated banks do not serialize their passes.

Maintenance clusters temporary reason projections and preserves original content vectors. ASP supplies paginated memory roots, resident recent usage, submemories and reasons. Continuation pages retain evidence checks and provenance revisions. Browsing suppresses both fresh and cached access updates. New crystallization modules separate metadata, matching, mutation and rollback. Superseded calendar code, settings, fixtures and documentation are removed.
