# Memory crystallizes the system's activity by its reasons

## Outcome

Memory becomes the system's durable activity record. Repeated compatible experiences crystallize into graph entities with recurrence, heat and reasons. Successful and failed outcomes remain distinct. The graph recursively organizes submemories by reasons and exposes usage and recurrence through ASP. Memory remains an independent project with the same clarity and code conventions as the host.

## Delivery

1. [Weighted graph knowledge](repeated-activity-becomes-weighted-graph-knowledge/prd.md) defines safe merging and recurrence.
2. [Durable activity intake](activity-recording-drains-into-memory-and-retires-calendar-history/prd.md) atomically drains inputs into the graph and retires calendar storage.
3. [Reason-space submemories](sub-memories-split-by-their-attached-reasons/prd.md) reuses semantic reasons for partitioning.
4. [ASP memory navigation](asp-shows-recently-used-memory-and-its-reasons/prd.md) exposes recent usage, groups, entities and reasons without changing usage while browsing.
5. [Standalone clarity](memory-stands-alone-with-clear-engine-and-integration-boundaries/prd.md) separates domain, persistence, orchestration and adapter responsibilities.

The companion root-board PRD typing-fuzzy-filters-every-scope-list covers local filtering across all Scope views.

## Acceptance

- [ ] The integrated graph preserves outcome and reason distinctions, recurrence and recorded representative output across restart.
- [ ] Acknowledged activity remains durable through embedding and commit failures.
- [ ] ASP exposes the same memory graph with bounded navigation and read-only usage projections.
- [ ] Memory builds independently and superseded calendar code, settings and documentation are removed.
- [ ] Focused tests, broader affected crate tests, repository audit and isolation checks pass on the integrated result.

## Boundaries

Transport, event dispatch and generic ASP contracts belong in the host base. Memory-specific similarity policy, graph reasons, recurrence and persistence belong in the independent memory project. Semantic crystallization does not promise reversible recovery of discarded wording; lossless storage and semantic condensation are different guarantees.

## Integration

The implementation is developed in .worktrees/memory-crystallization against recorded baseline 1d1bb31, preserving concurrent memory.ctg edits. Review histories live beside each leaf. The parent is complete only after integration evidence exists, not merely because its designs pass review.
