## Source facts

`src/rpc/src/experience/mod.rs::tool_trace` append currently returns `status: queued|duplicate` and a key, or a string error. It decodes input, serializes the normalized observation, obtains the durable store from the graph, then calls `experience_enqueue`. Acceptance follows successful LMDB transaction commit. Duplicate checks cover both pending inbox rows and committed receipts. Missing durable store is an error; no in-memory acceptance fallback exists.

`src/rpc/src/experience/input.rs` serializes the entire incoming argument object before validation and hashes those exact bytes using `util::content_hash`. The 64 KiB input bound includes the whole envelope. `src/cartridge/src/lib.rs::operation` removes `op` before RPC dispatch; `action`, `ts`, and other fields remain in the identity. `ts` must be an unsigned JSON integer. Missing, negative, floating-point, and string timestamps fail. An object-valued activity selects activity decoding, with existing permissive field defaults. Otherwise a nonempty user or response exchange is required. Do not accidentally replace this existing accepted-shape policy with stricter semantic validation.

`src/store/core/src/experience.rs::experience_enqueue` rejects timestamps older than seven days or more than 60 seconds ahead and rejects normalized observation bytes over 65,536. These checks occur before deduplication. It opens a write transaction, checks inbox/receipt duplication, checks 4,096 rows, 64 MiB intake bytes, and one million receipts, writes the row/counters, then commits. A replay outside the window is therefore rejected even if a receipt exists. Duplicate retries inside the window bypass capacity limits. These ordering choices must be explicitly retained or reviewed.

`StoreError` in `src/store/core/src/lib.rs` contains IO, LMDB, codec, version, and root errors. Semantic window/size/capacity errors are currently IO errors made from strings. Classification cannot safely inspect those strings. The experience module is private; a new public intake outcome/error type there requires an explicit re-export in core lib.rs, currently absent from this leaf's footprint.

The status lane replaces the old intake counters with strict versioned progress metadata, updates age-index/progress atomically on enqueue, and makes corrupt/missing/inconsistent metadata fail. New error sites include metadata read/decode/version/arithmetic checks, age-index writes, and metadata encoding/writes. These are storage/integrity failures, not malformed user input. The contract must use this collected authority, not revive old counters, repair corrupt state during append, or add parallel accounting. Status implementation is not yet an approved final baseline.

The manifest declares trace with a request schema requiring action and enumerating append/status/cycles/asp/drain. Base `cartridge.ctg/src/loader/document.rs::Event` uses deny_unknown_fields and supports only description, schema, timeout_ms, and frame. Adding a top-level response_schema or output_schema event field would break loading. Existing `.cartridge/tests/integration/asp.rs` declaration checks concern ASP and do not prove the append contract schema. Native engine tests are registered from `src/cartridge/src/lib.rs` to `.cartridge/tests/unit/src/cartridge/engine_test.rs`.

Attached-owner transport remains read-only: trace status/cycles/asp can be forwarded, append cannot. Native service construction/transport failures may precede RPC and remain transport errors. The tool.memory carve-out remains query/ingest; do not expose append through it.

## Proposed minimal contract decisions for review

Use an explicit opt-in version on append and a closed response with version, accepted/duplicate/retryable/rejected disposition, and bounded reason codes. Exact field and code names are specification decisions. Unversioned requests preserve their existing values/errors until coordinated runtime rollout. Unsupported or malformed version requests must fail closed before writing; an old endpoint's legacy queued response is not a valid acknowledgement of a requested new version. Transport errors remain failure, never durable acknowledgement.

Extract typed validation and enqueue reasons at their owning layers. Input errors and known timestamp/payload bounds are permanent rejection. Capacity is retryable. Missing store, LMDB/IO failures, corrupt progress, and codec/invariant failure are retryable/unavailable with bounded codes; this classification does not promise automatic recovery of corruption. Internal details may be logged, but must not become unbounded public reason codes or guessed input errors. Only committed enqueue or an existing durable duplicate can acknowledge.

Negotiation metadata must not silently change retry identity. Copy/remove only the new reserved negotiation field before applying the existing identity serialization, so the same old request and upgraded request can deduplicate across rollout. Do not strip evidence, timestamps, action, or previously hashed payload fields. Specify whether the external byte limit includes negotiation overhead and retain the independent normalized-size bound. A sender must retain its original timestamp and payload across retries; restamping a retry breaks both identity and expiry semantics. Root/host stamping of authoritative origin remains a runtime boundary concern.

Declare the request opt-in in the existing trace schema. Put the machine-readable response shape in a named local schema definition within that schema, with description/documentation identifying its role, if the host validator accepts it; do not apply the response shape as the request schema or add an unsupported Event field. Prove host declaration loading and actual request/response validation. This approach needs concrete independent review, not implicit approval from this report.
