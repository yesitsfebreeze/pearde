# Native public source records

The native `source.board` capability accepts `source_records`; `tool.prd` does not expose it. The configured boards directory is the only authority. `board` selects one local board, including a normal hierarchical selector; it does not recursively scan member boards. The caller obtains `expected_source_revision` from `source_declarations` and must send it on every index/read request.

Index request: `{op:"source_records",board:"root",action:"index",expected_source_revision:"<64hex>",deadline_ms:500}`. The reply schema is `cartridge-source-records/v1`. An available index contains `root`, `source_revision`, `action:"index"`, `items`, `index_revision`, `complete:true`, and `truncated:false`. Items contain only `path`, `title`, `bytes`, `revision`, and `visibility:"public"`, sorted by path. `index_revision` is SHA256 of the UTF8 `JSON.stringify({root,source_revision,items})` bytes in that field order. It describes public metadata only; changing only excluded private content does not enter the digest.

Read adds `path` and `expected_revision` and sets `action:"read"`. An available reply contains the same root/source identity, the selected item metadata, full exact UTF8 `text`, and `complete:true`. Hashes and byte counts cover original bytes, including BOM/CRLF. Read never substitutes another basename or truncates exact text. A missing or excluded private record returns the same static unavailable result.

Visibility is public only when `private` is absent/false and `visibility` is absent/public. Ambiguous, malformed, or unknown privacy values cannot authorize disclosure. Arbitrary frontmatter is never copied. Paths, titles, private counts and OS diagnostics from excluded records do not appear. Public frontmatter uses the owner parser’s strict mode with pinned yaml2, unique string keys and no aliases/merge keys or unresolved tags. Plain, quoted, escaped and flow duplicate keys are rejected before conversion. Trusted planner scan/edit retain their established Bun parser behavior.

Per operation: deadline1–2000ms (default500), source file1MiB, header16KiB, settings64KiB, total source reads8MiB (including failed reads and settings; record processing reserves64KiB for the final settings check), encountered directory entries4096, path components32, public items128, index wire1MiB and read wire8MiB. Scalar paths/title are bounded before serialization. Metadata capacity or unreadable entries yield bounded partial index items with `complete:false`, `truncated` for capacity, and static `reason:"source index incomplete"`. No paging or cache is introduced. A failure is only `{schema,status}` with status unavailable/changed/malformed/capacity/timeout; it never echoes unvalidated input.

Regular-file reads use nonblocking/no-follow opens, compare opened identity and final metadata, and close every handle. Selected directory identities and exact settings bytes are checked around each operation. These checks detect observable replacement; they do not create a filesystem transaction or protect against all external rename races. Native declarations and records share eight actual-I/O slots. A timed-out reply does not release its slot until issued OS work settles and handles close. There is no retry, journal, Memory call, event publication, CLI invocation, provider activation or source write.
