---
title: Board
description: The PRD orchestrator — scan, plan, dispatch, collect
---

The board is the product's spine: every piece of work lives as a PRD file
under `.pearde/prds/`, the scan parses the board once per mtime, the plan
names what runs next, workers are dispatched per PRD, and collect lands the
work one commit per PRD.

- **One file per unit of work.** A directory holding `prd.md` is a PRD;
  `specs/` under it holds the analyst-written implementable units. States are
  frontmatter, nine of them, moved by transitions the board itself guards.
- **No clock.** Order comes from `needs:`, footprints and the vision file —
  never from time, so a plan reads the same on every machine.
- **Workers are sessions**, each in its own worktree, dispatched with one
  brief command and answering DONE, BLOCKED, FAILED or REFUSED.
- **The board is one directory** at `.pearde/`, configurable, resolved the
  same way by scan, guard, doctor and the status line.
