Scout score: **58**. Root strength: every sweep leaves a dated record and the
findings never overwrite — discovery accumulates while nobody looks.

| axis | score | what pulls it up | what pulls it down |
|---|---|---|---|
| usability | 5 | one shell command per layer; `buckets.txt` is the single knob | four layers is three more than a newcomer needs; the sweep/delta/trending distinction is held in the head, not in the output |
| integration | 6 | findings feed the knowledge layer as citations, never copies | trending scrapes GitHub's HTML — layout-coupled, breaks upstream without notice; the stargazers API restriction left only self-diffing |
| sensibility | 6 | stars-as-discovery is a clean, defensible rule; the state column is honest | the curate layer (reading-list) has no tool behind it — hand-written rows with no regeneration, no check |
| complexity | 6 | three shell scripts, no dependencies beyond `gh` | snapshots, routes, findings and reading-list are four indexes a reader must tell apart |
| reliability | 6 | a row misalignment fails loudly, not silently | the HTML scrape and the TSV diff both assume yesterday's format exists; a missed day reads as a drop |
| performance | 7 | one search call per bucket, snapshots capped at 90 | — |

**Improve in this order:** usability (collapse the four commands into one
subcommand set that prints which layer it answered), sensibility (give the
reading list a check or a generator), reliability (name the missing-snapshot
case in `delta` output).
