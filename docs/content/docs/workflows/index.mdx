title: Workflows
description: How a kind of job is done, and improved on every run
---

A workflow says how a kind of job is done, and gets better every run.
Without the library every worker re-derives the *how*, and the last lesson
dies with its context.

- Two kinds, one flat directory: an **atomic** (one unit — what to do, how to
  tell it worked, how it fails) and a **workflow** (ordered atomics, why each
  is there, where a failure returns to). Exactly one slug key says which.
- **`runs:` on the frontmatter** counts every run; a report section per run
  folds the lesson back in — the library is the only part of the machine that
  is designed to be rewritten by its own output.
- **The library does not merge; only the refs do** — a slug resolves against
  its own board's library first, the master's second, like `needs:`.
- A PRD or a spec routes with `workflow: <slug>`; a dangling slug is a break,
  not an absence.
