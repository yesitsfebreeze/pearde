# invariants-are-testable-memos-and-the-kind-index-is-generated — a rule the board must not break carries the command that proves it

## Decision

`kind: invariant` joins `decision` and `note`. An invariant is the one
testable memo: it must carry `verify:`, a shell command run from the repo
root that exits 0 while the rule holds — required there, forbidden on every
other kind. `memo verify` runs every binding invariant (superseded ones no
longer bind); it is run at creation, so an invariant is filed proven, and
re-run whenever a change might bend one. A broken invariant is a stop, not a
warning. `memos/README.md` is the index by kind — generated by `memo index`,
rewritten on every `memo add`, and failed by `memo check` when stale.

## Why

A decision memo records a call; nothing ever re-asks whether it still holds.
Rules like "the board root stays clean" rot silently — the memo stays
`decided` while the tree drifts. Coupling the rule to a runnable command
makes drift detectable the way a test makes a regression detectable, and
naming the key `verify:` reuses the PRD contract's word for exactly that
job: a command whose exit code proves the claim. The index exists because
kinds now differ in consequence — an invariant binds, a note does not — and
finding "which rules bind" by opening twenty files does not scale. It is
generated because a maintained list beside a tree goes stale; the checker
comparing file to regeneration makes staleness a red, not a surprise.

## Alternatives considered

**Executing `verify:` inside `memo check`** — makes doctor slow and
side-effect-bearing; a health check that runs arbitrary shell commands on
every invocation is a different tool. Checking presence is cheap and keeps
the fast/slow split explicit: `check` proves the record is well-formed,
`verify` proves the world still matches it.

**A separate `invariants/` directory or file** — status-as-location was
already rejected for memos (moving a file rots inbound links); kind-as-
location has the same defect, and a second home splits the one-parser
contract memos.py holds.

**A new `broken` status** — the existing set already covers it: a broken
invariant either stops the change (nothing to record) or is dead and goes
`superseded` with its replacement named. A stored pass/fail would be a
cached test result, and cached test results lie.

**A hand-written index** — the board's most common defect, per the dotfiles
board's own memo on hand-kept lists standing in for properties of the tree.

## Consequences

- Every `memo add` rewrites `README.md`, so adding a memo touches two files
  in one commit — the price of an index that cannot drift.
- Existing boards fail `memo check` once until `memo index` is run — done
  for the dotfiles and pearde boards on 2026-09-01.
- `verify` commands are trusted shell run from the repo root; a slow or
  destructive command in `verify:` is a memo-author error the tooling does
  not police.
- `collect` runs them, and that is where the automatic reader landed. Step 2b:
  after the lane lands and after the board's `gate:`, before a byte of the
  record is written, every binding invariant's `verify:` runs against the
  merged tree, and one non-zero exit refuses the collect whole — the slug, the
  command and the script's own output printed, the PRD left exactly where it
  was. Wired by the PRD
  `no-work-is-lost-on-the-board/collect-runs-the-invariants-and-red-refuses`.
  Not doctor: the fast/slow split above still holds, and `verify` is still the
  reader a person runs by hand.
