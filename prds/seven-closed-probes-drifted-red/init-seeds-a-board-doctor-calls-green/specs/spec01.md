# spec01 — init finishes what it starts: the memo index after the copy, the graph the way upgrade plants it

`init --example` left two of the board's own parts half-planted, and doctor
said so on a board one command old: `memos broken · README.md: the kind index
is stale — run 'memo index'` and `knowledge broken · graph.json missing — run
relink`. Both are `init`'s to finish, and neither needs a new mechanism —
`memo index` and `knowledge.py board`/`relink` already exist and `upgrade`
already runs the second pair.

This unit adds two helpers to `init.py` and calls them from `cmd_init`, and
hands `upgrade` the second one so the two commands cannot drift apart.

**The two root causes, established by driving them, not by reading:**

- `write_board` copies the example board with
  `shutil.ignore_patterns("README.md")`. That pattern is matched in **every**
  directory the walk enters, not only the top one. It is there to drop the
  example board's own README — the page describing the example to a reader —
  and it drops `memos/README.md` with it. The board lands holding
  `memos/dates-are-written-not-stamped.md` and no index, and `memos.py`
  `check` reads a non-empty memo set against a missing page as stale
  (`memos.py:212`).
- `write_knowledge` plants the knowledge layer's *files* and runs neither
  verb. `cmd_upgrade` has always ended on `knowledge.py board` then `relink`;
  `cmd_init` did not. So the one command a newcomer runs left `wiki/` with
  notes and no `.graphify/graph.json`, which `knowledge.py doctor` reports as
  `graph.json missing — run relink`. This is **not** only an `--example`
  fault: an empty `init` board was red on the knowledge row too (seen under
  mutation M1 below, box `F doctor calls the empty board green too`).

**What already stands** — the whole unit is in the tree, uncommitted:

- `MEMOS_PY` beside `KNOWLEDGE_PY` at the top of `init.py`.
- `index_memos(board)` — subprocesses `memos.py index <board>` and returns the
  board-relative path written. Guarded: it returns `None` and runs nothing
  when `memos/` holds no `.md` other than `README.md`, so an empty board still
  lands with an empty `memos/` and no generated page sitting in it. The
  docstring says why regenerating beats teaching the copy to keep one file:
  the index is generated, `memo add` rewrites it, and a copied one is right
  only until the first memo.
- `plant_graph(board)` — the `board`-then-`relink` loop, lifted verbatim out
  of `cmd_upgrade`, returning one `(verb, first line)` pair per verb.
  `cmd_upgrade`'s inline loop is replaced by a call to it, so the two commands
  plant the same way by construction rather than by two copies agreeing.
- `cmd_init` calls `index_memos` before `write_knowledge`/`plant_graph` — the
  order is load-bearing, because `knowledge.py board` scans the memos the
  index is generated from — and prints one line per step, in `init:`'s voice.

**What the implementing pass added** — `index_memos` no longer returns `None`
in silence when `memos.py index` fails or prints nothing. It says what failed,
in `init:`'s voice, and names `memo index` as the repair. Found by attack, not
by re-run: `init` exited 0, printed nothing at all, and left a board doctor
immediately called `memos broken`. The happy path is byte-for-byte unchanged.

**What is left** — nothing in the footprint. `resources/memos.py`,
`resources/knowledge.py` and `resources/board/example/` are read and driven,
never edited.

## Acceptance

Every box below has been seen red. The mutations are named with the box, and
each was applied to the tree, run, and restored from a copy outside the repo
(`cmp` identical afterwards in every case).

- [x] A fresh `init --example` board holds `memos/README.md`, and
      `memos.py check <board>` exits 0 and prints nothing.
      **Seen red** on the pre-fix tree — the baseline before the first edit,
      and again under mutation **M1** (the `index_memos` and `plant_graph`
      calls deleted from `cmd_init`, nothing else):
      `FAIL B memos/README.md is on the board — got: no · want: yes`,
      `FAIL B memo check exits 0 — got: 1 · want: 0`,
      `FAIL B ...and says nothing — got: 55 · want: 0`. The 55 characters are
      `README.md: the kind index is stale — run 'memo index'`.
      **How to fail it again:** delete the `indexed = index_memos(board)` call
      from `cmd_init`.
- [x] The page on the board is the **generated** index, not a file that
      travelled in the copy — it carries the `<!-- Generated by 'memo index'
      and rewritten by 'memo add';` line `memos.render_index` writes.
      **Seen red** under M1: `FAIL B the index is the generated page, not a
      copied one — missing: <!-- Generated by 'memo index' …`.
      **How to fail it again:** as above; or make `write_board` copy
      `memos/README.md` instead of generating it, which passes the previous
      box and fails this one the moment the example gains a second memo.
- [x] The regenerated page is not merely *a* generated index but the **same
      bytes** the example board carries — `cmp` against
      `resources/board/example/memos/README.md` is silent. Without this, the
      previous box passes on any generated page at all, including one built
      from the wrong memo set.
      **Seen red** under M1 (`FAIL B ...and byte-identical to the example
      board's own page — got: differs · want: same`) and independently under
      mutation **M6**, which appends one comment line to the example page in
      a scratch copy of the repo and reruns `init --example` there: `cmp`
      reports `differs`. The repo was never written to.
      **How to fail it again:** M6 — change `resources/board/example/memos/`
      in a repo copy so the generated page and the committed one disagree.
- [x] A `memos.py index` that fails is **said**, not swallowed: `init` prints
      `init: could not regenerate memos/README.md, the memo index by kind —
      <what memos.py reported>`. A board holding memos and no index is one
      doctor calls broken on the very next line, so an `init` that exits 0 in
      silence has claimed a board it did not finish.
      **Seen red** under mutation **M5** — `index_memos` reverted to the bare
      `if out.returncode != 0: return None` it was written with, nothing else
      changed: `FAIL B a failing memo index is said, not swallowed — missing:
      init: could not regenerate memos/README.md`, `FAIL B ...naming what
      memos.py reported — missing: cannot write the index`, `41 checks · 39
      pass · 2 fail · 0 skip`, exit 1. The probe drives it by making the
      *copy's* `memos.py index` exit 1; the repo's copy is never touched, and
      the restore is proven with `cmp` inside the run.
      The tripwire beside it — `B the failing-index mutation reached the
      copy` — is itself falsifiable: under **M7**, the replace anchor in the
      probe broken so the mutation lands nowhere, it reads
      `got: 0 · want: 1` and all three go red (`41 checks · 38 pass · 3
      fail`). Without it, an anchor that stopped matching would make this box
      a check that cannot fail.
      **How to fail it again:** M5, or M7 for the tripwire.
- [x] A fresh `init --example` board holds `wiki/.graphify/graph.json`, and
      `knowledge.py --root <board>/wiki doctor` exits 0 saying `graph in
      sync`.
      **Seen red** under M1: `FAIL C wiki/.graphify/graph.json exists — got:
      no · want: yes`, `FAIL C knowledge doctor exits 0 — got: 1 · want: 0`,
      `FAIL C ...and calls the graph in sync — missing: graph in sync`.
      **How to fail it again:** delete the `for verb, line in
      plant_graph(board)` loop from `cmd_init`.
- [x] `doctor` over that board exits 0 and closes `pearde: every part this
      repo owns checks out.`, with the `memos` and `knowledge` rows reading
      the bare word `ok` — read as the row's verdict FIELD, never as a
      substring, because `ok` is inside `br·ok·en` and a `grep -F ok` over a
      row is a check that cannot fail. That mistake was made and caught in
      this probe: at first writing, `D the memos row is ok` passed against a
      row reading `memos broken 1 memos · 1 problem`.
      **Seen red** under M1 with the corrected reader:
      `FAIL D the memos row reads ok — got: broken · want: ok`,
      `FAIL D the knowledge row reads ok — got: broken · want: ok`,
      `FAIL D doctor exits 0 — got: 1 · want: 0`,
      `FAIL D ...and closes green — missing: pearde: every part this repo owns
      checks out.`
      **How to fail it again:** M1; or revert `verdict()` in the probe to a
      substring match, which turns this box green against a broken row and is
      exactly what the box is written to catch.
- [x] `init` prints what it did — one line naming the regenerated index, one
      per knowledge verb — so the board's first output does not silently
      differ from `upgrade`'s.
      **Seen red** under M1: `FAIL A ...and names the index it regenerated`,
      `FAIL A ...and the board verb of the knowledge layer`,
      `FAIL A ...and the relink that writes the graph`.
      **How to fail it again:** M1, or drop the three `print` calls.
- [x] An **empty** board — `init` with no `--example` — still lands with no
      `memos/README.md`, `init` claims none, and doctor calls it green.
      **Seen red** under mutation **M2** (the emptiness guard deleted from
      `index_memos`, nothing else):
      `FAIL F memos/ holds no generated index — there is nothing to index —
      got: yes · want: no` and
      `FAIL F ...and init claims none — present: regenerated memos/README.md`,
      `32 checks · 29 pass · 2 fail · 1 skip`, exit 1. The green half of this
      box was red too before the graph landed: under M1,
      `FAIL F doctor calls the empty board green too`.
      **How to fail it again:** delete the
      `if not any(f.endswith(".md") and f != "README.md" …): return None`
      guard in `index_memos`.
- [x] `upgrade` over a board `init` just made is a no-op for both parts — it
      exits 0, reports the wiki `already seeded`, and doctor is still green
      after it. This is what pins that the extraction into `plant_graph` did
      not change `upgrade`.
      **Seen red** under M1: `FAIL G doctor is still green after it — missing:
      pearde: every part this repo owns checks out.`
      **How to fail it again:** break `plant_graph`'s verb order, or make it
      raise — `upgrade` and `init` now share the one function, so either one
      failing fails both.
- [x] Nothing in this footprint is named by the repo's own index check.
      `python3 resources/index.py check` prints **115** problems and exits 1
      on this tree, and **not one of them is this unit's**: every line names

      the neighbour's and is **not repaired here**.
      **How to fail it again:** add a file under `resources/` without its
      manifest row — the check names it, and the second count above stops
      being 0.
