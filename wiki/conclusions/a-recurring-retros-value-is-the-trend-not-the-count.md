# a-recurring-retros-value-is-the-trend-not-the-count

A retrospective that reports only this period's numbers is a status update; what makes it a retro is diffing against exactly the last snapshot so a reader sees direction, not a point-in-time count, and per-person credit stays evidentiary — anchored to an actual commit — so praise and growth items read as findings rather than filler. Both rules protect the same thing: a reader months out should trust the report without re-deriving it.

Consequence: pearde's per-worker health data should snapshot the same way — one file per dispatch run, diffed against the immediately prior run, so board health reads as a trend across dispatches rather than a single tally re-computed from scratch each time.
