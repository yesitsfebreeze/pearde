# Claude Code PreToolUse payloads mark a subagent with agent_id and agent_type

A Claude Code `PreToolUse` hook payload distinguishes a dispatched subagent's
tool call from the main session's own — but not by the fields one would reach
for first.

Measured by dumping real payloads from a live round (11 consecutive calls,
several concurrent workers plus the main session):

- `session_id` is **identical** for the main session and every subagent it
  dispatches. So is `transcript_path`. One session, one transcript, for the
  whole round. Neither can separate a worker's call from the main session's.
- A subagent's payload carries `agent_id` (an opaque id, stable per subagent)
  and `agent_type` (the agent's registered name, e.g. `pearde-analyst`,
  `pearde-implementer`).
- The main session's own direct tool calls carry **neither** key.

Observed key set, subagent call:
  agent_id, agent_type, cwd, effort, hook_event_name, permission_mode,
  prompt_id, session_id, tool_input, tool_name, tool_use_id, transcript_path

Observed key set, main-session call: the same minus `agent_id`/`agent_type`.

Consequence for any hook that meters or budgets a session: a `PreToolUse` hook
fires in every agent session, subagents included, and a per-session token
measurement read off `transcript_path` returns the SHARED window. Metering the
main session's context and refusing at a ceiling will therefore refuse every
dispatched worker too, at a number that was never about them. Test
`agent_id`/`agent_type` to tell the two apart.
