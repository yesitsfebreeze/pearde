# BSD sed has no alternation in a basic regex, so a probe using backslash-pipe matches nothing and its check cannot fail

Every board harness on this machine runs under BSD sed (macOS), not GNU sed.
BSD sed does not support `\|` alternation or `\+` in a *basic* regular
expression. It does not error on them — it simply matches nothing.

That makes it a specific and quiet way to write a check that cannot fail. A
probe that reduces a doctor report to its rows with

    sed -n 's/^  \([a-z]*\) *\(ok\|broken\|off\) .*/\1 \2/p'

emits an empty string on every call. A diff of two empty strings is zero
lines, so the check reports a pass forever. The `-E` spelling works:

    sed -nE 's/^  ([a-z]+) +(ok|broken|off) .*/\1 \2/p'

GNU sed accepts the basic-regex spelling, which is why it gets written.

Two consequences for probes here:
- use `sed -nE` with a bare `(a|b)` group, never `\(a\|b\)`;
- pin the extractor with a tripwire — assert it read N rows, not zero —
  because a silent extractor turns every check built on it green.

Related: a second shape of the same defect is matching a verdict as a
substring. `grep -F ok` over a doctor row matches `br`ok`en`, so a box
asserting a row "is ok" passes against a broken row.
