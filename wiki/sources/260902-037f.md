# Odin rejects circular package imports at compile time, so the build is the cycle check

The Odin compiler rejects a cycle between packages at compile time: two packages that import each other fail with `Error: Cyclic importation of <pkg>` before any codegen. Probed on odin dev-2026-08 by building a three-package fixture (a imports b, b imports a, main imports a) — the build never produced a binary.

Consequence for a board that lists "no circular package dependencies" as an acceptance box: the ordinary build IS that check. A separate cycle-detection script over the import graph is a check that cannot fail differently from `odin build`, and adds a second thing to keep true.

A per-package `odin check <dir>` is a different and still-useful check: the whole-project build only reaches packages the entry point transitively imports, so a package no one imports yet can rot unseen. `odin check` on a library package always emits `Undefined entry point procedure 'main'` — that one line is expected and must be filtered.
