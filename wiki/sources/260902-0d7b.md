# just vendor leaves the vendor gate red until git add vendor

In mitosys, `cargo test -p mitosys-gates` cannot pass immediately after `just vendor`: `vendor_is_complete::nothing_under_vendor_is_untracked` fails because the refilled tree is on disk and in no commit. Measured 2026-09-02 during the `conserved` → `shared` rename: 21 untracked files under `vendor/shared-0.1.0`, and the gate's own panic message names the fix — "If `just vendor` just produced them, `git add vendor` is the whole fix". After `git add -A vendor` the same run is 122 passed, 0 failed, exactly the pre-rename baseline.

Consequence: any PRD that re-vendors and then asserts a gate baseline must put `git add -A vendor` between the two, or its acceptance box reports a regression that is only an unstaged directory.
