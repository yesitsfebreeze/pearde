# cargo vendor fetches through a directory source replacement; cargo check does not

Measured in realm on 2026-09-02 while renaming the vendored `conserved` crate to `shared`. With `.cargo/config.toml` holding a `[source."git+…?rev=<new>"]` stanza replaced by a directory source, and that directory holding STALE bytes (package still named `conserved`) under `shared-0.1.0/`:

- `cargo check --workspace --offline` fails hard: `error: no matching package named \`shared\` found / location searched: directory source … (which is replacing https://github.com/yesitsfebreeze/shared.git?rev=dfc98fb…)`. A plain `mv` of the vendor directory is therefore NOT a false green when the package name changes; the false green exists only for a same-name rev bump.
- `cargo vendor --versioned-dirs <out>` under the same config succeeded and produced `<out>/shared-0.1.0/Cargo.toml` with `name = "shared"` — it fetched the rev `Cargo.toml` names instead of reading the replacement directory.

Command: `cargo check --workspace --offline --config 'source.shared-vendored.directory="<stale>"'` and `cargo vendor --versioned-dirs --config 'source.shared-vendored.directory="<stale>"' <out>`.
