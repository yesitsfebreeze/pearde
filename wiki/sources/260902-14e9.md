# television 0.15.9 always contributes ten baked-in channel names

`tv list-channels` never drops below ten entries, even with an EMPTY cable
directory (`XDG_CONFIG_HOME` pointed at a scratch dir with no
`television/cable` at all): `bash-history`, `dirs`, `docker-images`, `env`,
`files`, `git-branch`, `git-diff`, `git-log`, `git-repos`, `text`. These are
baked into the `tv` binary itself, not read from any file — `strings` on the
homebrew binary shows the embedded default config, including
`border_type = "rounded" # https://docs.rs/ratatui/...`, which is also the UI
default for every border (`input_bar`/`results_panel`/`preview_panel`) that a
config.toml need not restate.

Consequence for anyone counting channels: the union with a project's own
cable files is what `list-channels` reports, so an acceptance number written
against "however many `.toml` files are in our cable dir" undercounts by the
names that don't overlap a builtin. Measured for a 10-file cable dir (`dirs`,
`docs`, `files`, `git-log`, `nu-history`, `quicklist`, `recent-dirs`,
`recent-files`, `text`, `theme`): 4 names overlap a builtin (no net add), 6
are new, giving 16 total — one over a "15" ceiling nobody had reason to
suspect without running the empty-dir baseline first.
