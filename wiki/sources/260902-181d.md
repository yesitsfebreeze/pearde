# pearde ships no binary — the shell wiring is an alias plus an exported PEARDE_AS, and install only prints them

`pearde install --apply` builds symlinks for the skills and then PRINTS two
lines for you to add to your shell yourself — it writes no shell file. Both
are named at references/install.md:68 and resources/install.sh:217:

    alias pearde='python3 <repo>/resources/pearde.py'
    export PEARDE_AS=engineer

Two things this makes true. There is no `pearde` on PATH — `which pearde`
answers "not found" on a machine where every skill is installed, because the
tool is a python entry point and nothing links it into a bin directory.

And the two lines are a pair, not a convenience each. Measured 2026-09-02:
`pearde sweep --dry` with PEARDE_AS unset exits having done nothing, printing
`refused — persona: --as <id> on the line, or PEARDE_AS in the environment`;
with it set the same command runs. Every subcommand that MOVES a PRD reads it
to stamp `· as <id>`.

`persona` is not a pearde subcommand — `pearde persona` answers "unknown
command `persona`". Switching is the export re-run in your own shell, which is
also why an alias (a child process) could never do it for you.
