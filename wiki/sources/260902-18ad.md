# claude-tmux binds C-j in tmux root table, pane-conditional, so nvim window-down survives

claude-tmux.nvim installs its `<C-j>` toggle as a ROOT-table tmux binding that is
conditional on the Claude pane id, not as a nvim keymap:

    bind-key -T root C-j if-shell -F "#{==:#{pane_id},%1}" "select-pane -t %0" "send-keys C-j"

Measured 2026-09-02 in a private tmux server (`tmux -L npprobe`, 200x50 client)
against the deployed `~/.config/nvim/lua/plugins/claude.lua`, firing `:ClaudeCode`
from a real headless nvim inside a pane. Consequences: nvim's own `<C-j>`
window-down map is untouched, because the binding never reaches nvim — tmux
intercepts it and, outside the Claude pane, passes it straight through with
`send-keys C-j`. The same run confirmed the split lands on the RIGHT (pane %1 at
left=140, 60x50 of a 200x50 client) with no `split_side` key set at all — a second,
independent reproduction of the forced-right merge already on record.
