# knowledge.py resolved its wiki from the script, so every lane read an empty record

Measured 2026-09-02 while probing a-lane-s-wiki-is-a-stub.

`resources/knowledge.py` resolved its store from the SCRIPT, not the cwd:
`default_root()` was `Path(__file__).resolve().parent.parent / "pearde" / "wiki"`.
Every other board reader (`memos.py`, `grammar.py`, `health.py`, `questions.py`,
`workflows.py`, `plan.py`) climbs from the cwd with `board_above`.

A lane is a git worktree at `<board>/.lanes/<slug>` materialised WITHOUT the
board directory on purpose (@resources/board/lanes.py `create`), so it holds a
checkout of knowledge.py and no wiki beside it. Script-relative therefore
answered `<lane>/pearde/wiki`, `Store.ensure` created it, and the query the
analyst brief tells every worker to run first reported `0 notes on record`
against a record holding 82 — silently, no error, once per worker.

The cost, counted on this board the same day: 26 lanes held stub wikis with 34
notes — 29 pending gaps re-asking questions already queued, and 5 `remember`
findings that `git worktree remove` would delete. One other PRD's harness was
red on it: `one-definition-of-the-board-not-two/probe/verify.sh` reported
`knowledge.py board wrote 0 PRD note(s), disk has 139` from a lane, and went
green the moment the resolver climbed.

The lane's own `pearde/` is not mistaken for the board: it holds only the
shared graphify cache, so it carries neither `settings.md` nor `prds/` and
`is_board_dir` walks past it to the live board two levels up.
