# grep -F reads a multi-line pattern as one pattern per line

`grep -F -- "$needle"` with a needle containing newlines does not match the
newlines. `-F` splits the pattern argument on newlines and matches any one of
the resulting fixed strings, so a two-line needle succeeds when **either** line
appears anywhere in the input.

A shell assertion helper of the shape
`has() { printf '%s\n' "$2" | grep -F -- "$3"; }` therefore degrades silently
when given a multi-line needle: the assertion reads as "this exact block is
present" and tests "at least one of these lines is present".

Measured, not inferred: re-wrapping the clause the needle names — moving one
word across the line break, changing no word — left the harness reporting `ok`
on that check and its totals unmoved at 24 pass / 29 fail.

To assert a multi-line block, compare the whole file text in a language with
real substring matching (`python3 - <<'PY' ... assert block in text`), or match
a single line.
