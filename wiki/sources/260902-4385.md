# Claude Code opens one socket per live session at /tmp/cc-socks/<pid>.sock

Claude Code keeps a directory `/tmp/cc-socks/` holding one Unix socket per
live session, named `<pid>.sock` where `<pid>` is the pid of the session's own
`claude` process.

Measured 2026-09-02 on this machine: `/tmp/cc-socks/` held `3971.sock`,
`52794.sock`, `60704.sock` and `91661.sock`, and `ps -eo pid=,command=` showed
a `claude` process at each of those four pids and no other. Walking the process
tree up from a shell inside a session reached `claude` at pid 60704, and
`60704.sock` was present for it.

Two consequences for anything that has to decide whether a session is alive:

- The socket is corroboration, not proof of death. A session whose socket a
  cleanup removed is still a session, so an absent socket must never on its own
  decide that a session is gone.
- The pid it is named after is the identity a process-tree walk finds, so the
  socket and the walk agree without either having to be told about the other.

`ps -o lstart= -p <pid>` is the pid-reuse guard that goes with it: second
resolution, stable for the life of the process, and available on both macOS and
Linux. `etime` is not usable for this — it counts up.
