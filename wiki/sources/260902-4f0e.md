# Ollama's embedding endpoint is /api/embed, and /api/tags is what tells an embedder from a reasoner

The current endpoint is `POST {base}/api/embed`. Its request key is `input`
and its reply key is `embeddings` — a LIST of vectors, one per input, because
it batches. The retired `/api/embeddings` took `prompt` and answered with a
bare `embedding`; code written against the old shape decodes nothing from the
new one.

Measured live 2026-09-02 against `qwen3-embedding:0.6b`: one input returned
exactly one vector of 1024 components. A single-input caller should therefore
refuse a reply carrying any other count rather than take the first element —
taking the first silently picks one of several answers to a question that had
one input.

`GET {base}/api/tags` reports a per-model `capabilities` array. An
embedding-only tag carries `["embedding"]` and no `"completion"`, which is how
an embedder and a reasoner are told apart without attempting a call. Older
servers omit the field entirely, so a filter must decide what absence means —
and the two directions are not symmetric: a wrong reasoner pick fails loudly
at the chat call, a wrong embedder pick answers with a vector that means
nothing.
