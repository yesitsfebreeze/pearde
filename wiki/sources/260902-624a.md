# target/debug/deps keeps every stale hash of a test binary, so a perf harness must take the path from cargo's --message-format=json executable field and never from a glob

[[260902-bb0e]] says to run the built test binary directly rather than
`cargo test`, because concurrent cargo invocations serialise on the
target-directory lock. It does not say how to find the binary, and the obvious
answer is wrong.

Measured in mitosys on 2026-09-02: `target/debug/deps` held **seven** distinct
`determinism_conformance-<hash>` binaries and seven `ingest_at_seq-<hash>`
binaries at the same time. Cargo never prunes the old ones. A glob or an
`ls -t` picks one arbitrarily, so a harness that finds its subject that way
times a build nobody made and reports it as the current suite's cost.

The `executable` field on a `compiler-artifact` message from
`cargo test --workspace --no-run --message-format=json` names exactly the
binary this build produced, for every artifact whose `profile.test` is true.
That is the only reading that is current, and it is the same single command
that has to run anyway to avoid the lock. So the JSON step is not an
optimisation over globbing — globbing has no correct version.
