# cargo fingerprints a vendored package by its checksum file, not by mtime

Cargo does not use mtime to decide whether a vendored package is fresh: a package supplied through a directory source replacement carries a .cargo-checksum.json, and cargo fingerprints it from that file rather than from the mtimes of its sources.

Measured in /Users/feb/dev/infra/realm on 2026-09-02 while proving an acceptance box that wanted the 'Checking shared v0.1.0 (...?rev=dfc98fba...)' line in cargo's output. Two consecutive runs of 'touch vendor/shared-0.1.0/src/lib.rs && cargo check --workspace --offline' printed only 'Finished dev profile ... in 0.03s' and no Checking line. 'cargo clean -p shared --offline' followed by the same cargo check printed it on the first output line.

Consequence: any check that wants to observe a vendored dependency's resolved source URL or rev in cargo's own output must clean that package first. Touching a file under vendor/ is a no-op for this purpose.
