# A repo-walking gate must root at src/, never glob from the repo root, or every open pearde lane reads as an offender

`.pearde/.lanes/<prd>/` is a git worktree — a whole second checkout of the
repository, `src/` included. A checker that does `Path(root).rglob("*.rs")`
therefore sees N+1 copies of every file, one per open lane, and any
"exactly one file may do X" rule reports every lane as a duplicate.

Measured: a one-dispatch-core check reported 56 dispatcher files across 11
lanes; rooting the walk at `<root>/src` gave the true answer, 1. Two other
symptoms of the same walk: `Path.rglob("src/**/*.rs")` double-counts (rglob
already recurses, so every hit is reported twice), and the counts printed are
silently doubled.

The sibling failure already on record is the reverse — a gate rooted at its own
file was green inside a lane and had 93 findings on `main`, because the lane
has no `.pearde/`.
