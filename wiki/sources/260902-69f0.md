# A leading ! exempts a command from set -e — a verify-block line written ! grep … can never fail the block

POSIX.1-2017 XCU 2.11: the `set -e` rule does not apply to a command whose exit status is inverted by a leading `!`. The shell prints the failure and carries on, and the block's exit becomes the next command's.

Measured here on darwin bash 3.2.57 and on bash 5, both under `bash -e -o pipefail -c`, which is the pair `collect` runs a spec's `## Verify and Proof` block with (resources/board/collect.py:1242). A line written

    ! grep -n X file | grep -q Y

therefore cannot fail the block: its passing case and its failing case both leave the block at exit 0. Found in spec05 of `every-worker-runs-in-its-own-worktree` — the mutation that should have reddened it did not. The portable replacement is

    if grep -n X file | grep -q Y; then exit 1; fi

which aborts under `-e` on the failing case. This is the same class as the `<test> && <action>` shape @references/workflow.md's `write-the-specs` already names; the `!` form is the one it does not.
