# nu -c loads no config, so a nushell config change is tested with --env-config and --config

Measured 2026-09-02 on nushell 0.115.1. `nu -c '<code>'` runs with NEITHER
env.nu nor config.nu loaded: after deploying `$env.PEARDE_AS = "engineer"`
into ~/.config/nushell/env.nu, `nu -c 'print ($env.PEARDE_AS? | default
"UNSET")'` printed `UNSET`, and `$env | columns | where $it =~ "PEARDE"`
returned an empty list.

The trap is that unrelated variables still LOOK loaded — EDITOR and
STARSHIP_SHELL both answered, because they were inherited from the parent
process, not read from env.nu. So checking a familiar variable is not a test
that config loaded; only a variable you just added is.

The form that does load both is explicit:

    nu --env-config ~/.config/nushell/env.nu --config ~/.config/nushell/config.nu -c '<code>'

which printed `engineer` for the same expression, and resolved aliases
defined in config.nu.
