# mitosys is the one consumer still pinning the family crate as conserved@70d7e15 and the committed vendor tree hides the drift

The family crate `shared` (github.com/yesitsfebreeze/shared — NOT inner-zirkle/shared, which the mitosys PRD names) was renamed from `conserved` on 2026-09-02 at rev dfc98fb. `../model/Cargo.toml:39` and `../realm/Cargo.toml:65` both pin `shared = { git = ..., rev = "dfc98fb..." }`; mitosys `Cargo.toml:376` still pins `conserved = { ..., rev = "70d7e15c..." }`.

Nothing in mitosys can notice. `.cargo/config.toml` replaces every dependency source with the committed `vendor/`, and cargo takes whatever the replacement directory provides, so `vendor/conserved-0.1.0` builds green against a package name and a rev the remote no longer serves. model and realm each carry a vendor-check script that catches this; mitosys carries none. The producing side gate is `shared/tests/landed_rev_is_published.rs`, which fires from inside the shared repo only.

Both revs are on origin/main, so the current mitosys pin is fetchable — the defect is drift, not a dangling rev. The diff 70d7e15..dfc98fb over the crate source is the rename and nothing else: no API moved.
