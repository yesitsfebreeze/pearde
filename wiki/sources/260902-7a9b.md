# keymodel stopsel only covers cursor keys, never hjkl

Setting `vim.o.keymodel = "startsel,stopsel"` reproduces shift-arrow select
and collapse-on-plain-arrow (normal and insert mode, including the
"catches two characters not one" quirk on insert-mode `<S-Right>`) with no
custom Lua at all — but only for the cursor keys. `:help 'keymodel'` says so
literally: "stopsel: Using a not-shifted special key stops selection...
Special keys in this context are the cursor keys, <End>, <Home>, <PageUp>
and <PageDown>." Confirmed by a headless-nvim keystroke fixture: after a
shift-started selection, an unshifted `j` EXTENDS it exactly like a
`v`-started selection would; only an unshifted arrow key collapses it.

Two traps for anyone reusing this option:
1. `termguicolors` and `keymodel`-driven selection both need a REAL pty to
   observe. `nvim --headless -u NONE` under-reports `termguicolors` as
   false even with `COLORTERM=truecolor` set; only a run inside an actual
   tty (tmux worked) showed the terminal-detected `true`.
2. `'keymodel'`'s `stopsel` cannot distinguish how a selection began: a
   plain `v`-started selection now ALSO collapses on the next unshifted
   arrow key (previously it correctly extended, matching stock vim) —
   `hjkl` are unaffected either way, only the special/cursor keys carry the
   collapse behaviour.
