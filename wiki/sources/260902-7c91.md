# A pearde lane worktree breaks a PRD's ../sibling-repo paths

A PRD written against a checkout at `/Users/feb/dev/infra/<repo>` may quote verify commands of the form `git -C ../shared branch -r --contains <rev>`. A pearde lane worktree sits at `<repo>/pearde/.lanes/<prd>/`, so `../shared` resolves to `<repo>/pearde/.lanes/shared`, which does not exist.

Measured 2026-09-02 in mitosys: `ls ../shared` from the lane fails while `/Users/feb/dev/infra/shared` is present. Such a command then fails with "not a git repository" rather than failing the check it was written for — a check that errors out is not a check that passed, and an implementer reading only an exit code can mistake one for the other.

Consequence: a PRD whose verify reaches a sibling repository must use an absolute path, or resolve it into a variable once at the top of the block.
