# A hand-rolled HTTP server that closes the socket to end a body cannot be wrapped in TLS unchanged

`connection: close` — writing the answer and dropping the `TcpStream` — is the
ordinary way a small HTTP/1.1 server signals end-of-body. Over TLS it is a
truncation, not a close: rustls refuses an EOF with no `close_notify` with
`peer closed connection without sending TLS close_notify`, so a strict TLS
client errors on *every* response, not on a malformed one. The server must call
`conn.send_close_notify()` and drive one more `complete_io` before dropping.

Measured 2026-09-02 against rustls 0.23.43, vendored in mitosys, in the
p10c-remote-auth probe. The shape of the failure is the useful part: the three
assertions that only checked a *bad* client was refused (no certificate, wrong
CA, revoked) all passed on the first run, and the single assertion that read a
body back was the only one that failed. A mutual-TLS test suite written to
prove refusals will therefore be green while every real client is broken.
