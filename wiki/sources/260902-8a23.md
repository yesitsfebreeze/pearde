# rm -rf . deletes nothing on darwin

BSD `rm` refuses the operands `.` and `..` outright — `rm -rf .` prints
`rm: "." and ".." may not be removed`, exits 1, and deletes nothing. GNU
coreutils `rm` behaves the same way for the bare `.` operand, so this is not
a darwin-only refusal, but on darwin there is no `--no-preserve-root`-shaped
escape that changes it.

The consequence for this repo: a probe that proves a guard by running
`rm -rf .` inside a fixture proves nothing on this machine — the block is a
no-op and the guard is never exercised. A check built on it passes whether
the guard is there or not.

What actually empties a working tree while leaving the repository intact:

    find . -mindepth 1 -not -path './.git*' -delete

A block that removes `.git` as well is past anything git can put back, so a
guard built on stash/checkout/update-ref is not measured against it.
