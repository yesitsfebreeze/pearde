# A grep names dead dependency candidates; only removing the line and rebuilding makes one a fact

mitosys ran this exact sweep before kern did, and both of its commits state the
method rather than the result.

`1523b882` ("15 more dead direct dependencies, found by verifying every OWNERS
pair") wrote a script over every (dep, owner) pair, then verified each of the 15
hits the hard way — remove the line, `cargo build -p <crate>`, watch it still
succeed — "not trusted from a grep alone (grep says nothing about whether a
build actually needs a name)". The commit also names the shape precisely: a
declared dependency doing nothing is the same defect as one used only in tests —
a main-manifest line with no main-code reason to exist. `async-stream` and its
`async-stream-impl` macro crate dropped out of the lockfile entirely once their
single declarer let them go; kern freed the same two names from the same crate
for the same reason.

`cd1ca82f` names the second shape: a server resolves a relative runtime path
(`intake.dir`) against `current_dir()`, which under `cargo test` is the crate
root, so a fixture that does not name a temp dir leaves a live store inside the
crate directory — and the next `git add -A` commits it. mitosys had to untrack
six intake payloads that way. Its own message calls the `.gitignore` line a
stopgap: an ignored store is an invisible store, so the assertion that actually
holds is a working-tree walk, not an ignore rule.
