# BSD wc on macOS pads its count, so wc -l piped into grep -qx never matches

BSD `wc` on macOS right-pads its count with spaces: `wc -l` prints `       3`, not `3`. A verify block written as `… | wc -l | grep -qx '3'` therefore never matches and reports a failure on a tree that is green — the failure is in the check, not the subject.

The portable form is `grep -c ''`, which prints the bare number: `test "$(cmd | grep -c '')" = 3`. GNU coreutils `wc` does not pad when it reads a pipe, so the same line passes on Linux and fails on this machine — a verify block that only ever ran on Linux hides the defect.

Measured on darwin 25.2.0 running spec03's verify block for the-worker-parts-are-rewritten-dense; `python3 resources/index.py check | wc -l | grep -qx '3'` exited 1 while the command it wrapped printed exactly three lines.
