# A code repo hosted under the board makes every footprint read as a board path

Measured 2026-09-02 while making board commands resolve a run session's own
worktree as the code repo.

`collect.foot_root` decides whether a footprint path belongs to the board's
repo or the code repo by joining the path onto the code repo and testing the
absolute result for the board's directory as a string prefix. That test is
sound only while the code repo sits ABOVE the board.

A session's worktree is `<board>/.sessions/<id>` — below it. The moment that
worktree is what a command means by "the code repo", `os.path.join(repo, p)`
puts every footprint path inside the board by prefix, and `foot_root` files
all of them in the board repo, which holds none of them. Measured: `collect`
printed `p1: in the board's own repo, not the lane's — src/app.py`, then
`outside the footprint, left in the lane — src/app.py`, ran the verify
against an unchanged tree, and committed nothing. No exception, no wrong
answer named — the footprint was simply routed away from the lane.

Lanes live under the board too (`<board>/.lanes/<slug>`) and never trip this,
because `land_lane` passes the CODE repo as `repo` and only the lane's path
is under the board.

What measured clean: anchor the containment test to the checkout — the tree
the worktree was cut from — whenever `repo` itself resolves inside the board.
A worktree and its checkout spell every tracked path identically, so the
answer holds for both.

Second measured detail, same function: compare with `realpath`, not
`abspath`. This board is reachable as `pearde/` and as the `.pearde` symlink
beside it, and a session tree named through one while the board is named
through the other compares unequal under `abspath`.
