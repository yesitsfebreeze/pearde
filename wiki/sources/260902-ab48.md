# A git pre-commit hook cannot be re-homed as a pearde gate: without being rewritten

`gate:` in `.pearde/settings.md` is one command run in the repo root by
`collect`, on the MERGED tree, after the lane`s commit and before the record
commit. Nothing is staged at that moment.

So a hook whose subject is `git diff --cached` — the whole class of
pre-commit gates — takes its empty-index early-exit there and reports green on
every PRD, forever. It is the "gate that cannot go red" failure reintroduced by
the act of moving the gate somewhere more visible.

Re-homing one means rewriting it as a diff of HEAD against the merge base,
which is a second program with a second set of edge cases, not a second home
for one rule.
