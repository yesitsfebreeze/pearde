# Turbopack refuses a symlinked node_modules in a git worktree

A `pearde` lane is a git worktree, and a worktree gets no `node_modules` of its
own. Symlinking the main checkout's directory in is the obvious move and it
fails: `npm run build` dies with

    Error [TurbopackInternalError]: Symlink [project]/node_modules is invalid,
    it points out of the filesystem root

Turbopack resolves the project root and refuses any symlink escaping it, so
lint, tsc and tests all pass and only the build step goes red — which reads as
a code fault rather than a setup one.

Two things that do work, measured on darwin/APFS:

- `cp -Rc <main>/node_modules <lane>/node_modules` — a copy-on-write clone.
  768 MB in **7.1 s** wall, costing almost no disk until a file diverges.
- `npm ci` in the lane. Correct, and minutes rather than seconds.

`.gitignore`'s `node_modules/` entry has a trailing slash, so it matches a
directory and **not** a symlink of that name: the symlink also shows up as `??`
in `git status`. The clone does not.
