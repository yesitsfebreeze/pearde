# tmux display-popup never format-expands -e, only -d; run-shell is what expands

`display-popup -d '#{E:@cwd}'` IS format-expanded; `display-popup -e
'VAR=#{pane_id}'` is NOT — the twelve literal characters `#{pane_id}` reach
the popup's environment. Measured three ways on tmux 3.7c: as the direct
argument of a key binding, as the body of a `command-prompt` template, and
through `run-shell`. Only the `run-shell` route produced a real pane id,
because it is `run-shell` doing the expansion on its own argument before the
shell ever sees it — the same rule a generated `bind-key` loop leans on, and
the reason a literal `#{...}` inside one must be written `##{...}`.

So the way to get a real pane id into a popup is to route the popup through
`run-shell`, and when the popup is the body of a `command-prompt` template,
to write the template as a tmux `{}` block: a backslash-continued quoted
template does not survive the nesting and the binding silently never fires.
