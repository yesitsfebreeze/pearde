# A board whose .pearde is a git worktree defeats repo_root's walk-up, so every footprint resolves to nothing

`plan.repo_root` walks up looking for `.git` with `os.path.exists`. A git
worktree writes `.git` as a *file* holding `gitdir: …`, not a directory, so
`os.path.exists` sees it and the walk stops there.

On this repo `.pearde/` is a worktree of the code repo
(`.pearde/.git` = `gitdir: /Users/feb/dev/infra/pearde/.git/worktrees/-pearde`).
So `repo_root('/Users/feb/dev/infra/pearde/.pearde')` returns the board itself,
`prd_repo` returns the board, and every PRD footprint on this board resolves
under `.pearde/` where no such file exists.

Measured 2026-09-02: `newest_mtime` over the footprint of
`leaked-background-services-outlive-their-fixtures` reads `0.0`; all 8 paths
report `exists=False`. A plain `.pearde/` (the dotfiles board) resolves to the
code root correctly, which is why this shows on one board only.

Readers affected: `silent_of` (claim staleness), `collect`'s commit union, and
any cross-board footprint comparison. The fix is to walk from the board's
parent, not the board.
