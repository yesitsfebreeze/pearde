# A SessionStart hook exiting 2 does not block a headless session in Claude Code 2.1.258

## What

The hooks reference says of `SessionStart`: *"Exit Code 2 — Prevents the
session from starting. Uses stderr as the blocking reason."* Measured, it does
not, in `claude -p`.

| hook command | session | output |
|---|---|---|
| `echo BLOCKING-REASON >&2; exit 2` | started, answered normally | the model's answer only |
| `python3 .../serve.py ensure` (exits 2 outside a board) | started, answered normally | the model's answer only |
| `python3 .../serve.py ensure >/dev/null 2>&1 \|\| true` | started | the model's answer only |

Claude Code 2.1.258, macOS, project `.claude/settings.json`, headless `-p`.
Interactive mode was not measured — the difference may be mode-specific.

## What follows

The wrapper `>/dev/null 2>&1 || true` on a SessionStart command is still the
right shape: it is the only spelling that is exit 0 and silent in **both**
readings, and a wiring that depends on which reading is true is a wiring that
breaks on an upgrade. Do not drop it on the strength of this measurement.
