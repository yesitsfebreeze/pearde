# A worktree cut from a repo that tracks its .pearde board carries a phantom board

Measured in a fixture repo on 2026-09-02 while probing every-worker-runs-in-its-own-worktree.

When the code repo TRACKS its board (`.pearde/` committed rather than gitignored), `git worktree add` materialises a stale copy of the board inside the new worktree. A worker whose working directory is that worktree runs a board command and the walk-up finds the copy, not the live board: `pearde scan` printed `0 PRDs` from inside the lane against a live board holding one. It is silent — no error, a board with nothing in it.

The fix that measured clean:

    git worktree add --no-checkout <dir> -b <branch>
    git -C <dir> sparse-checkout set --no-cone '/*' '!/.pearde'
    git -C <dir> checkout

The lane then holds no board dir at all and `pearde scan` from inside it resolved to the live board. The excluded path keeps its skip-worktree bit, so a later `git add -A` inside the lane commits only what changed and leaves `.pearde` standing in the tree — confirmed with `git ls-tree HEAD --name-only`.

Related hazard, same layout: a lane directory placed under a TRACKED board dir is an embedded git repository to the outer checkout. A person running `git add -A` in the checkout gets `warning: adding embedded git repository` and a broken gitlink. The board's own `.gitignore` must carry the lanes dir the way it already carries `.claims/`.
