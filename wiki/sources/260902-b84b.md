# BSD grep BREs have no backslash-pipe alternation, so a verify assertion written that way can never fire

macOS ships BSD grep, whose basic regular expressions have no `\|` alternation — `\(a\|b\)` matches the literal text, not either branch. GNU grep accepts it as an extension, which is why the form is common in scripts written on Linux.

Measured 2026-09-02 in kern. A spec verify block asserted 'no folded changelog entry states future work' as:

    ! grep -n '^- 2026-08-0[67] .*\(will be\|remains open\)' docs/CHANGELOG.md

A deliberate violation was inserted into a 2026-08-06 entry and the block stayed green. Rewritten as `grep -nE '...(will be|remains open)'` it went red immediately.

The consequence is that an assertion of this shape is not merely weak, it is unfalsifiable on a mac: it passes on the violation it was written to catch. Any negated-grep assertion with BRE alternation has to be watched red before it is trusted.
