# nushell keybindings dedupe by name, not modifier+keycode

Measured on nushell 0.115.1, 2026-09-02. `$env.config = ($env.config |
upsert keybindings ($env.config.keybindings | append [...]))` does not
just concatenate: reading `$env.config.keybindings` back after two
appends that share the same `name` field (different modifier casing,
different event) yields ONE entry — the later one — not two. Two records
with the SAME name and the SAME (modifier, keycode) collapse to the
later append; two records with the SAME (modifier, keycode) but
DIFFERENT names both survive as separate list entries (confirmed: this
repo's own `hist_picker_local` and the generated `tv_history`, both
Ctrl-R, coexist in the raw list — reedline's last-entry-wins resolves
the actual key dispatch between those at runtime, per the existing
manual comment). So `event: null` reliably unbinds a generated
keybinding only when it reuses that binding's exact `name` — matching
(modifier, keycode) with a different name does not unbind anything, it
adds a second binding reedline then arbitrates between at dispatch time.
Isolated repro: a bare `nu -n -c` script with two `upsert keybindings`
calls sharing a name shows length 1 both times; the deployed shell
(config.nu + the generated `tv init nu`) shows the same collapse for
`tv_completion` while keeping both `hist_picker_local` and `tv_history`
as distinct Ctrl-R entries.
