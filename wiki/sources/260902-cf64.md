# A SessionStart hook exiting 2 blocks the session from starting

## What

Claude Code 2.1.258, project `.claude/settings.json`, event `SessionStart`.

| fact | value |
|---|---|
| valid matcher values | `startup`, `resume`, `clear`, `compact`, `fork` — pipe-separated |
| `matcher` omitted | the entry fires on every start reason (measured) |
| stdin payload | `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `source` (measured; the docs name that last key `reason`) |
| `cwd` | the project directory the session started in |
| stdout, exit 0 | debug log only — not shown to the user, not in the `-p` output (measured) |
| exit 1 | non-blocking error; the session starts |
| **exit 2** | **prevents the session from starting**; stderr is the blocking reason |
| execution | through a shell (`sh -c` on macOS/Linux) — `;`, `>`, `\|\|` all work (measured) |
| default timeout | 600s, per-hook `timeout` key overrides |
| fires in | `claude -p`, `--continue`/`--resume`, `/clear`, after compaction |

## Why it matters

Any command wired to `SessionStart` that can exit 2 will lock the user out of
their session. A CLI that exits 2 on "wrong directory" — `serve.py ensure`
prints `pearde: no .pearde/ board found walking up from the cwd` and exits 2 —
must be wrapped `>/dev/null 2>&1 || true` before it goes in that slot. The
`|| true` is the safety property, not tidiness.

## Measured

- `sh -c 'python3 .../serve.py ensure >/dev/null 2>&1 || true'` — exit 0 both
  inside a board and outside one.
- cold (no daemon): 0.16s. warm (daemon up): 0.05s, three runs.
- A `SessionStart` hook running `serve.py ensure` in a scratch board started
  the daemon and registered the board; `serve.py status` listed it 1s later.

## Whether subagents fire it

Undocumented.
