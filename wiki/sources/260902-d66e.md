# std::env::set_var is safe in edition 2021 and unsafe in edition 2024, so an edition bump turns every unguarded test env write into a compile error

In edition 2021 `std::env::set_var` and `std::env::remove_var` are safe fns. In edition 2024 they are `unsafe` fns, because a write races every reader thread in the process and the standard library cannot make that sound.

Consequence for this tree: kern's workspace is `edition = "2021"` (Cargo.toml:7), so the three unguarded writes in `src/config/src/tests/config_test.rs:47,50,51` compile silently today. An edition bump turns each of them into a compile error, which forces the environment guard whether or not the board reaches that PRD first.

This is why the process gate's env check is worth having before the bump rather than after: it names the sites now, with a contract attached, instead of the compiler naming them all at once during a migration.
