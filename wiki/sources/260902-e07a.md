# A local ollama embedder is not bit-reproducible across identical calls

The same text, through the same tag, on the same server, in the same process,
returns two DIFFERENT vectors. Measured 2026-09-02 against
`qwen3-embedding:0.6b`: components differ by roughly 1e-6, cosine similarity
between the two answers is 0.999999977, and `a == b` is false.

Semantically the drift is nothing — two different texts sat at cosine 0.5964
in the same run, four orders of magnitude further apart. Two consequences
follow anyway:

- A test asserting equality of two embeddings of one text FAILS, and looks
  like a flake. Assert cosine above a threshold instead.
- A tree that replays a record by folding it byte for byte cannot put a raw
  embedding call inside that fold. The vector has to be stored with the record
  and replayed from it, not recomputed — otherwise the replay does not
  reproduce, and the "verification comes from outside" property is lost.

The cause is not identified here; the usual suspects are non-deterministic
reduction order on a GPU or thread-count-dependent batching. What is measured
is that it happens on a default local install with no flags set.
