# wait -n needs bash 4.3, so a job cap on macOS /bin/bash must poll jobs -r

`wait -n` — wait for the next background job to finish, rather than all of
them — was added in **bash 4.3** (released 2014). It is the idiomatic way to
hold a job cap in a shell loop.

macOS ships **bash 3.2.57** as `/bin/bash` and has since 2007, because bash
moved to GPLv3 in 4.0 and Apple will not ship it. `wait -n` therefore does not
exist on any stock macOS `/bin/bash`; it exits 2 with `wait: -n: invalid option`.
A Homebrew bash on PATH does not help a script whose shebang is `#!/bin/bash`.

The portable bash-3.2 equivalent is to poll the shell's own job table before
each launch:

```sh
while [ "$(jobs -r 2>/dev/null | grep -c .)" -ge "$CAP" ]; do sleep 0.1; done
cmd &
```

`jobs -r` lists only running jobs and works in a non-interactive shell. A
`while read ... done <<EOF` loop does not put its body in a subshell, so jobs
started inside it are visible to `jobs`. Measured holding an exact cap of 3
over 12 jobs on bash 3.2.57 (arm64-apple-darwin25).
