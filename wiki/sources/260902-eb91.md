# worktrunk (wt) manages worktrees and keeps no session ledger

`worktrunk`, on the PATH as `wt`, is installed on this machine at
`/opt/homebrew/bin/wt` (Homebrew cellar `worktrunk/0.72.0`), version v0.72.0.
It describes itself as "Git worktree management for parallel AI agent
workflows".

Its whole command surface, from `wt --help`:

    switch   Switch to a worktree; create if needed
    list     List worktrees and their status
    remove   Remove worktree; delete branch if merged
    merge    Merge current branch into the target branch
    step     Run individual operations
    hook     Run configured hooks
    config   Manage user & project configs

What it does **not** carry, checked against that surface:

- **No session ledger.** `list` lists worktrees; nothing records which process
  holds which, or when it took it.
- **No liveness test.** There is no notion of the holder of a worktree being
  alive or gone, so nothing decides what is stale.
- **No snapshot before removal.** `remove` deletes the branch when it is
  merged; nothing puts uncommitted or untracked work into the object store
  first, which is the one property that would have saved work lost to a
  `reset --hard`.

So worktrunk owns the worktree and neither the ledger nor the reaping. A tool
that wanted both would use it for `switch`/`remove` and still have to build the
ledger, the liveness test and the snapshot itself — three of the four parts.
