# bash reading a script on stdin loses every statement after a stdin-reading command

`bash -e -o pipefail` fed a script on stdin (`subprocess.run(..., input=script)`)
reads it statement by statement from the same descriptor its commands inherit.
The first command in the script that reads stdin with no file operand and no
redirect — a bare `cat`, `grep PAT`, `sort`, `wc`, `python3 -` — consumes the
REST OF THE SCRIPT as its input. Every statement after it never runs, and bash
exits with the status of the last statement it reached, which is 0.

Measured: the block

    bash -c 'echo "3 passed, 2 failed"' | tail -1
    cat
    bash -c 'echo "3 passed, 2 failed"' | grep -q '0 failed'
    echo reached-the-end

exits 0 on stdin, and the last two lines come back on stdout printed by `cat`.
The same block as `bash -e -o pipefail -c "$block"` with stdin closed exits 1.

Fix: pass the script as a `-c` argument and close stdin (`stdin=DEVNULL`).
