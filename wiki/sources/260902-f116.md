# a bang-prefixed assertion is exempt from set -e, so it cannot fail a verify block

A negative shell assertion written as '! cmd' is exempt from 'set -e': POSIX says the -e setting is ignored when a command's status is inverted by '!', so a violated assertion does not stop the script and the block goes on to print its success line. Measured 2026-09-02 with 'set -e; ! true; echo REACHED' under /bin/sh on darwin 25.2.0 — REACHED prints and rc is 0. A verify block asserting absence must use 'if cmd; then echo FAIL; exit 1; fi' instead. Same family as 'grep -c' exiting 1 on a count of 0: the failure mode is a check that cannot fail.
