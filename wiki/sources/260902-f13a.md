# television 0.15.9 ships ten built-in channel names, and a cable file can shadow one

`tv list-channels` does not read only `~/.config/television/cable`. Ten names
are compiled into television 0.15.9. Measured against a fixture holding an
empty `television/cable` and nothing else:

    XDG_CONFIG_HOME=<empty fixture> tv list-channels
    -> bash-history dirs docker-images env files git-branch git-diff git-log
       git-repos text   (10)

A cable file whose name is one of those ten does not add a row — it *shadows*
the built-in. So the list length is not the file count plus a constant:

    len(tv list-channels) = 10 + files - shared

where `shared` is how many of the ten the cable directory also supplies. The
gap between the list and the directory is `10 - shared`, and it MOVES whenever
an adopted or retired file's name collides with a built-in.

Measured 2026-09-02 during `09-simplify/retire-the-unmanaged-television-channels`,
both readings reproduced by the formula:

    23 files, shared 6 (dirs files git-diff git-log git-repos text)
      -> 10 + 23 - 6 = 27, and 27 is what `tv list-channels` printed
    19 files, shared 6 (same six)
      -> 10 + 19 - 6 = 23, and 23 is what `tv list-channels` printed

The gap held at 4 across both readings only because `shared` did not move: the
nine adopted `git-*` files include `git-diff` and `git-repos`, which are
built-in names, but those files were already ON the machine before the landing
— adoption moved them into the chezmoi source, not onto the disk chezmoi reads
for this list. What moved the machine was the four removals, none of them a
built-in name, so the list fell by exactly four alongside the directory.

Watch the same directory across the two readings, or the arithmetic will not
close: the *source* directory of ten files that the repo owned before the
landing shares only four built-in names (`dirs`, `files`, `git-log`, `text`),
so its gap is `10 - 4 = 6`, not 4. Two directories, two `shared` counts, two
gaps — which is the whole reason the gap is not a constant.

Consequence for any retirement: assert the directory count, which you own, and
never `tv list-channels`, which you do not. A retirement of a shadowing file
can leave the list length unchanged while the directory shrinks, and a
retirement of a non-shadowing file moves both — so a correct apply can read as
one that did nothing, in either direction.

Supersedes the first version of this note, which named four built-ins
(`bash-history`, `docker-images`, `env`, `git-branch` — the four the 19-file
directory happened not to shadow) and read the gap as a constant 4. An earlier
note still on the dotfiles board names only `env` and `git-branch`; that is the
same error, further out.
