# obsidian-unhide 3.1.0 ships its own DEFAULT settings object, and it is the rule syntax to copy

The minified bundle of polyipseity/obsidian-unhide 3.1.0 carries its own defaults literal:

    showingRules: ["+/", "-/\\.git(?:\\/|$)/u", "-/\\.venv(?:\\/|$)/u"]
    protectSync: true
    showHiddenFiles: true
    showConfigurationFolder: true

Three things follow, and none of them is in the README.

A rule is a sign then a target: `+` or `-`, then either a plain path (`+/` — the vault root, which is what turns hidden files on at all) or a delimited regex with flags (`/…/u`). The backslashes are doubled because the rule is a JSON string holding a regex, so `\.git` is written `\\.git` in `data.json`. A preset that gets that escaping wrong matches nothing and the plugin says so nowhere — it simply indexes what the rule failed to exclude.

`protectSync` is already true in the plugin's own defaults, so shipping it true in a preset changes nothing; shipping it false would be the change, and the one that risks the Sync data loss.

`showConfigurationFolder` defaults true, which means `.obsidian/` itself is indexed unless a rule excludes it. A vault preset that does not exclude it puts every plugin's `data.json` — the REST API key among them — into the vault's own search index and graph.
