# A probe crate green on cargo check and cargo test can still be red on just check

mitosys gate is `just check` = cargo fmt --check --all, then cargo clippy --workspace --all-targets -- -D warnings, then cargo test --workspace. A probe crate set can pass `cargo check` and `cargo test` for its own packages and still leave that gate red on the first two stages, and nothing in a spec whose acceptance boxes name only check/test will catch it.

Measured 2026-09-03 on p10a1-element-catalog: the widget probe crates were fmt-dirty in three files (rustfmt.toml is hard_tabs + tab_spaces 2; run `rustfmt --edition 2021 <files>`, the workspace edition, not 2024), and clippy::only_used_in_recursion failed the build on `pub fn render(w: &Widget, ctx: &WebCtx)` — a renderer context struct whose field nothing read, passed down only to the recursive call. Deleting WebCtx/TuiCtx (Capabilities stays in the catalog crate) was the fix; a context nothing reads is a knob that only looks like one.

Corollary for a spec writer: put `just check` in the Verify and Proof block of any PRD that adds a crate. Per-package check+test is not the repo gate.
