# Claude Code's session scratchpad is shared between concurrent sessions on one machine

Claude Code gives each session a scratchpad path that reads as private and is not: on this machine `/private/tmp/claude-501/<project>/<uuid>/scratchpad` held 125 entries from several concurrent sessions.

A worker that saves a build to a bare `<scratch>/build.patch` before reverting its footprint to take a baseline loses the build: a neighbouring session wrote its own `build.patch` and `build-backup/` to the same paths 2m23s later, and the `git apply` that was meant to restore the build applied the neighbour's hunks into this lane instead. `git apply` returned 0 — the patch was valid, just not the one that was saved.

Two rules follow. Write every file a run saves under `<scratch>/<run-id>/`, not at the scratch root — the same rule pearde's `capture-the-harness-baseline` already states for harness outputs, which does not name the build patch. And verify the round trip rather than assuming it: `md5` the footprint files before the revert and diff the checksums after the restore, because a successful `git apply` proves nothing about which patch it applied.
