# content-addressed-rustc-wrapper-caches-restore-by-hardlink-or-reflink

A content-addressed RUSTC_WRAPPER (blake3 keys over normalized compiler inputs) separates the two goals a shared target dir conflates: each worktree keeps its own target/, so no lock contention and no parallel-build corruption, while compiled artifact bytes live once in a shared store. Restore is a hardlink on ext4/WSL2 or a reflink on btrfs/XFS/APFS — filesystem support decides which, and removing the wrapper from config fully reverts either way since the store bytes are inert. The tradeoff: incremental compilation is disabled while the wrapper is active, so a changed crate recompiles fully even though its unchanged dependencies still hit the cache.
