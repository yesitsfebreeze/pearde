# os.getcwd() returns the resolved path, so a cwd-derived board path is already realpath'd

POSIX `getcwd(3)` returns an absolute pathname with every symbolic link
resolved, and Python's `os.getcwd()` is a thin wrapper on it. Measured on
macOS 25.2.0 (2026-09-03): a child process started with `cwd=<a symlink to
a directory>` reports the TARGET's path from `os.getcwd()`, never the link's
spelling.

Consequence for this tree: any board path derived from the cwd — `run.board_at()`,
and so every `pearde run` with no scope word — is already realpath'd before
anything compares it. Two invocations from two spellings of one directory
cannot reach the dispatcher carrying two different spellings; only a path
read out of the watch set or a `members:` list can. A refusal that only prints
the physical board "when the two spellings differ" therefore never prints it.
