# spec verify blocks that name a board path fail in a lane unless PEARDE_ROOT drives them

A `## Verify and Proof` block run from a lane cwd cannot use repo-relative paths: the lane holds no `.pearde/` board and the probe it names lives on the orchestrator's board. Shape that works both ways: run the block from the checkout root (where collect runs it), resolve `ROOT="${PEARDE_ROOT:-$(pwd)}"` for every module path and file read, keep the probe/board path repo-relative (`.pearde/prds/<prd>/probe/...`), and let the probe resolve its own tree from PEARDE_ROOT (the harness preamble shape: walk up to the `.pearde` holding the probe, `ROOT="${PEARDE_ROOT:-$(dirname "$BOARD")}"`). Board-wide gates (`index.py check`, `health.py check`) get captured (`out=$(... 2>&1) && rc=0 || rc=$?`) and gate only on lines naming footprint paths; a producer exit of 1 means findings, >=2 means crash (PRD enforce-pointer-not-verdict, spec01, 2026-09-03).
