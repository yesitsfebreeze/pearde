# an acceptance box asserting git status shows the new files goes stale the moment a sibling's collect commits the board repo

spec02's box "git status --short shows the new files — the board repo commits its own" was green when the prior pass ran it and red two hours later, with nothing changed but time: the board's commits are split by rebuilt blob, and a sibling session's collect (3bf5ead "ramp-is-a-doctor-row-not-a-gate") took this PRD's uncommitted wiki notes with its own. The check the box means is "the files are tracked in the board repo and absent from the code repo" — assert that shape: `git -C .pearde ls-files -- <dir> | grep -q <name>` (tracked, covers uncommitted and committed) beside the existing `test -f`, plus the code-repo-side `git status` refusal. A bare status grep is a check that can only fail before the merge, never after.
