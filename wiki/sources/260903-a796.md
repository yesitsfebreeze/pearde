# git add cannot stage a committed deletion, and a lane merge moves the index

Measured on pearde, 2026-09-03, git 2.55.0 (macOS):

1. `git add -- <path>` and `git add -A -- <path>` both fail with
   `fatal: pathspec '<path>' did not match any files` when the path is
   deleted in the worktree AND no longer in the index (the deletion was
   committed). `-A` stages a deletion only for a path still tracked in
   the index; a committed deletion is untracked, and no add flag can
   match it. So "stage the deletion with -A" is not a fix for a lane that
   already committed its deletion — the deletion needs no staging at all:
   the merge carries it. Stage only the standing (dirty) intersection of
   the footprint, never the whole union.

2. A worktree deletion of a still-tracked file (` D path` in porcelain)
   IS staged by plain `git add -- <path>` — no -A needed.

3. After a `git merge --ff-only` that carries a deletion, the checkout's
   INDEX no longer holds the deleted path (the merge rewrote it). A guard
   that asks `git ls-files` to decide "does this repo hold the path" says
   no for a path the repo just deleted. History answers: `git log -1
   --format=%H -- <path>` is non-empty for any path some commit carried,
   empty for a path that never existed.
