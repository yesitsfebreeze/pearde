# collect's open-box gate cannot measure a box that names another PRD's collect

collect refuses any PRD with an open acceptance box — including a box that says "sibling PRD collects", which can only be measured after this PRD lands, which collect refuses to do while the box is open. The deadlock has no flag: --trust skips the verify, not the box check; --fail only fires after a red verify, which the gate never reaches. Measured 2026-09-03 on the-module-split-dropped-the-merged-read-plan-all-boards-slo. The way out that exists today: the worker releases claimed→blocked with `needs: <sibling>` (the state table's "waiting on a named event — open boxes"), writes `## Blocked` naming what closes each box, commits the board record, and the sibling's own landing re-opens it (unblock's gate is `needs:` all done). The box then gets ticked by whoever measures the sibling's collect — in this run, the same worker, after unblock, because the sibling's PRD-half (the plan reads) had landed and its run.py half was the sibling's own claim still in flight. A box whose event is another worker's landing should be written `blocked`, not ticked-on-faith.
