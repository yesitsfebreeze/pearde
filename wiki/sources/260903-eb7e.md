# git add refuses an explicit pathspec under an ignored directory even when the file is tracked

`git add -- <path>` exits 1 with "The following paths are ignored by one
of your .gitignore files" when the named path resolves inside an ignored
directory — even when the path is already tracked and the add would only
record a modification or a deletion. The ignore check is on the pathspec,
not on the file's tracked state.

`git status --porcelain` is unaffected: a tracked path's dirt is always
reported regardless of .gitignore, and without `--ignored` it never lists
an untracked-ignored file. So any code that reads status and then feeds
the paths back to `git add` must pass `-f`, and `-f` there cannot widen
what gets swept in — status already excluded the fresh ignored files.

In this repo: collect.py's PRD-folder staging step (`git_out(root, "add",
"-f", "--", *p["add"])`) hit this once `.pearde/.gitignore` gained
`prds/**/probe/` while dozens of probe files were already force-tracked.
