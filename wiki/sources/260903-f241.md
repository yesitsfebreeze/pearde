# shared-cargo-target-dir-serializes-parallel-worktree-builds

A single shared CARGO_TARGET_DIR across git worktrees looks like the obvious fix for duplicated target/ dirs, but cargo takes an exclusive lock on the build directory, so concurrent cargo build/check/test across worktrees serialize instead of running in parallel (rust-lang/cargo#4282, #16790 — corruption races on top of the lock contention). sccache does not close the gap either: it skips proc-macro/bin/dylib crates (anything hitting the linker), requires incremental compilation off, and does not dedupe target-dir disk at all. Cargo's own native shared build cache (#5931) is unshipped — the workaround has to live outside cargo until it lands.
