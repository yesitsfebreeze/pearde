# docker-port-conflict-decision-tree-lsof-then-container-or-process

sudo lsof -i :<PORT> identifies the PID and process name holding a blocked port first, before touching Docker at all. If docker ps -a shows that PID's container, docker stop <container> sends SIGTERM for a graceful shutdown; kill -9 is reserved for a process that ignores docker stop, and sending it to a container skips its cleanup — last resort, not the default move. If the blocking process isn't Docker at all (a local dev server bound to the same port), stop that process or remap the container's port instead of killing anything. A container that exits immediately after starting is diagnosed with docker logs <container>, not lsof — the three named causes are a missing required env var (check .env/docker-compose.yml), a broken CMD/ENTRYPOINT path, or an OOM kill (raise Docker Desktop's memory limit). "Cannot connect to the Docker daemon" means Docker Desktop itself isn't running: open -a Docker, then wait for the steady whale icon before retrying.
