# A lane loses its board link when cut inside a session, or cut before link_board existed

lanes.create's link_board silently no-ops (returns None with no error) when the claiming process's own repo argument resolves to a SESSION worktree nested INSIDE the board (.pearde/.sessions/<id>), because board_rel(board, repo) treats any relpath starting with '..' as "not under this repo" — true for a genuinely unrelated path, but also true here, where board is repo's ANCESTOR rather than a sibling or descendant. Confirmed live: board_rel('/repo/.pearde', '/repo/.pearde/.sessions/s85810') returns None on today's resources/board/lanes.py. collect.repo_of prefers exactly that nested session worktree once session.held() matches, so any lane cut by a claim running inside an active session inherits this. Separately, lanes cut before link_board existed in the checkout's own history never get the symlink retrofitted, because create()'s idempotent reuse path (an existing worktree dir) never re-runs link_board. Measured on this machine: 7 of 45 .lanes/* worktrees under .pearde/.lanes have no working link to the board.
