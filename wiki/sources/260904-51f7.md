# cypress-e2e-stays-flat-page-objects-hold-selectors-testrail-ids-prefix-titles

E2E tests live under tests/cypress/ in plain JavaScript, no TypeScript. Each test opens with cy.visit() for clean state, closes on a real assertion, and skips describe/context nesting entirely — each it() is flat and self-contained, since nested blocks add no value for a linear E2E flow. cy.wait() is banned: a fixed delay doesn't track real load time and is the standard flakiness source, replaced by a timeout option on the specific element being waited on. retries: { runMode: 3, openMode: 0 } absorbs remaining CI flake without masking a real fixed-delay bug locally. The Page Object pattern puts one class per page under support/pages/<area>/: each locator is its own method returning a cy.get() chain, plus one composed action method (login(user, pass)) driving several locator methods in sequence — a test imports the class, instantiates it once, and calls the composed method, so no selector string appears inline in a test body. TestRail integration runs through the cypress-testrail plugin; every it() title is prefixed with the case ID (it("C1234: should login successfully", ...)) — that prefix is the only coupling between the test file and TestRail.
