# release <prd> failed left its lane standing, unlike sweep's own reclaim to failed

`cmd_release` in resources/board/transitions.py only called `transition(...)`
on every edge, including `claimed -> failed` — it never called `drop_lane`.
`cmd_sweep`'s own silent-reclaim path, moving a stale claim to the same
`failed` state, already called `drop_lane` right after `transition`. Two
routes into the same state disagreed on lane cleanup because the cleanup
lived beside one caller instead of behind the edge itself.

Fix: call `drop_lane(board, rel, who="release")` from `cmd_release` too,
guarded on `to == "failed" and not args.dry`. `drop_lane` gained a `who=`
label (default "sweep") so its printed line credits the edge that actually
called it, since a `release`-triggered drop reading "sweep: ... removed"
would misname the cause.

`release <prd> failed` also takes the branch `lane/<slug>` when `## Failure`
says the run is not to be retried — `drop_lane` itself never deletes a
branch (by design, per its own docstring: an unmerged lane is work the
machine holds). The new `lanes.delete_branch` is a second, explicit step,
gated on a regex match against the `## Failure` section text:
`not\s+(?:to\s+)?be\s+retried`, case-insensitive — matches "not be retried"
and "not to be retried". No prior convention for a "do not retry" marker
existed anywhere in the repo before this pass; this phrasing is now the one
a `## Failure` section writes to mean it.
