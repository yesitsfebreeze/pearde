# a doctor row must take the exit code, not only grep the output

A doctor row that derives its verdict from grepping a `$(python3 …)` subshell's stdout reports `ok` when the subshell crashed: the traceback goes to the capture, the grep counts zero matches, and the zero reads as clean. The house pattern for this is the `health` row — it takes `HRC=$?` on the line after the capture and branches on the exit code before it looks at the text. Rows added without that guard (the `lanes` row was written this way first) are checks that cannot fail. The check that catches it costs two lines in a probe: `chmod 000` the directory the python walks, run doctor, expect `broken`.
