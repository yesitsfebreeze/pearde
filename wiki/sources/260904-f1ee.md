# vitest-config-mirrors-vite-aliases-mocks-cleared-in-both-hooks

vitest.config.ts mirrors the app's Vite path aliases (~, @, ...) exactly in resolve.alias — the single most common "cannot find module" failure is this file drifting out of sync with vite.config. test.globals: true plus "types": ["vitest/globals"] in tsconfig.json removes per-file describe/it/expect imports. environment: "node" is the default and fastest choice; jsdom/happy-dom apply only when a test touches the DOM. Test files end .test.ts, live beside their source or under test/, and read "should <expected behavior>" (it("should return empty array when input is empty")). vi.clearAllMocks() and vi.unstubAllGlobals() run in both beforeEach and afterEach, not just one — a mock or stubbed global that survives from the previous test is the standard cause of an intermittently failing suite. A composable under test is re-imported per test with a dynamic await import() after vi.resetModules(), so module-level state (a cached ref, a singleton) doesn't leak between cases.
